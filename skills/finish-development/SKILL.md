# Finish Development

判断证据是否足以完成，并在用户要求时处置提交、PR、分支或 worktree。实现与根因调查的缺口交回调用方；可补的验证直接完成。

## 证据与完成

完成声明须有真实、可复查的证据，覆盖当前内容、相关依赖、配置与环境。已有有效结果直接复用，只在改动、失败或未解疑点需要时补最小验证，保留项目明确门禁。

按声明选择证据：文档核对引用、结构和关键语义，代码验证目标行为，UI 检查实际交互与视觉。操作指引、安全、数据、性能或稳定性风险需对应观察；功能通过不代表性能未退化，单次绿色不能证明 flaky 修复。

bugfix 以原失败场景和根因机制为锚点。可安全重跑且有覆盖价值时优先重跑；minimal 按额外价值复验。原场景不可复跑时，说明替代证据保留与缺失的条件，分别报告代码修复和原环境验收状态，不能用浅层通过替代。

报告实际完成内容、证据路径和剩余缺口；命令、退出码、提交与时间必须来自可复查记录，未知不编造，无关字段省略。本次临时产物须有处置记录。证据充分即结束，验证完成不自动进入 Git 处置。

## 提交与工作树

dirty 工作树可以验证，证据对应实际内容。只有基于特定提交的声明或操作才需绑定提交：核对被测内容、依赖、配置与环境一致后可映射已有证据；提交标识参与构建时检查其影响，目标提交的 CI 门禁仍须满足，不能把映射说成该提交已运行 CI。

用户要求处置时，按目标与当前状态选择提交、PR、合并、保留或丢弃；不要求用户遍历固定菜单。不提交或目标处于 detached HEAD、外部管理状态时，说明对所请求交接的实际限制。

提交、push、PR、合并、删除前，核对既有明确授权是否覆盖分支、提交范围、远端和 worktree 路径；已覆盖即继续，目标、范围或风险实质变化才重新确认。测试通过不扩大授权。

清理 worktree 还须核对未提交和未推送内容、活跃使用及管理归属。来源不明或存在未授权数据损失时保留；目标与删除已获授权且状态可确认时，不受创建者身份限制。外部管理工作区遵循其管理入口，创建 PR 或选择保留不自动授权清理。

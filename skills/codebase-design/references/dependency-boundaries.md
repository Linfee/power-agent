# 依赖边界与 seam

用于依赖边界或测试隔离仍不清楚时，按运行性质细化主文件的 seam 判断。

| 依赖 | 默认设计 | 测试策略 |
|---|---|---|
| 进程内、确定性协作 | 默认直接组合；算法或不变量复杂时用窄模块接口封装 | 优先用真实对象验证稳定行为 |
| 本地可替换逻辑 | 已有真实变体时收敛 interface；单一实现不预建多态层 | 用真实变体或必要的最小替身验证契约 |
| 自己拥有的远程组件 | 保留协议与副作用边界，不伪装成普通本地对象 | 按验证目标选契约 / 集成测试或边界替身 |
| 第三方服务、文件系统、时钟等外部效应 | 在 effect 边界隔离；interface 尽量窄 | 按需在边界使用替身，保留目标所需的真实集成验证 |

## 加深后替换旧层

将多个浅层模块合并为更深的模块后，删除旧的转发路径，以及只断言旧私有层的重复测试。测试应通过新的公开接口验证可观察行为，而不是保留对被隐藏实现的耦合。

## 检查

- 调用方是否必须知道本应由 adapter 隐藏的供应商、请求格式或资源管理细节？若是，边界可能过浅；消费者本来必须遵守的生命周期义务则应明确留在契约中。
- 测试是否耦合了契约未要求的内部结构？若是，优先观察稳定行为；重试次数、发送顺序或持久化结果本身属于契约时可直接验证，不为断言形式另造接口。

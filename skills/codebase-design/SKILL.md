# Codebase Design

设计深模块：让调用方通过易理解的接口使用足够多的行为，同时把应由模块承担的复杂度留在内部。先看实际调用者、需求、已有契约和依赖；使用项目已有领域术语，不为形式新建术语文件。

## 理解模块

- **模块**可以是函数、类、包或一段跨层实现；它有供调用方使用的**接口**和内部实现。
- **接口**不仅是签名，还包括使用者必须知道的不变量、调用顺序、错误、配置、性能和资源责任。不要用隐藏必要语义换取表面简单。
- **深度**是接口提供的能力与它要求调用方理解的负担之间的关系，不按接口/实现行数计算。**Leverage** 是调用方获得的能力；**locality** 是相关知识、改动和验证集中在一起的程度。
- **Seam** 是可在不修改该位置代码的情况下改变行为的位置；测试切入点是观察行为的位置，两者可能重合但并非同义。**Adapter** 是在 seam 处满足接口的具体实现；内部 seam 不必公开。

用删除测试判断：删除模块后，复杂度是否消失，还是流回调用方、破坏不变量或让资源责任难以维持？只有转发而没有实际责任的层可内联；即使只有一个消费者，集中复杂算法、生命周期或不变量也可能值得保留。不要以模块数、方法数或代码行数代替整体复杂度判断。

## 选择边界

从消费者需要的结果和真实运行性质选择直接组合、内部隔离或稳定 adapter。第三方 I/O 的协议隔离、独立资源所有权或消费者依赖的不变量都可能证明单实现边界有价值；仅为测试替身而需要替换，不能独立证明公开多态接口必要。远程依赖不自动要求 port，也不按 adapter 数量判定 seam 是否真实。按实际行为和风险选择真实组件、契约测试或替身。

依赖性质与安全加深的细节见 [dependency-boundaries.md](references/dependency-boundaries.md)。用户要求比较，或高影响、长期接口存在会改变决定的真实取舍时，读 [design-it-twice.md](references/design-it-twice.md)；无需为凑数设计候选。

给实施者说明接口、调用约束、隐藏的复杂度、边界理由与可观察验证入口；需要用户决定的取舍与代码可查事实分开。不因设计建议自动扩大实现授权。

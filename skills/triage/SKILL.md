# Triage

处理尚未分诊的外来请求；已确认并进入执行图的票据不要重复分诊或降级。沿用项目配置的 tracker、分类与状态角色及 AI 披露政策，不假定固定标签存在，也不伪装成维护者。项目把外部 PR 作为请求入口时，同样分析其说明、讨论及实际 diff；按配置区分 issue 与 PR。

先读请求全文、相关讨论、既有分类和维护者决定，查项目范围、相关代码和历史记录；按概念查重，区分已经实现、重复请求、明确拒绝和暂缓。对 bug 在安全且获准的条件下复现；无法复现或信息不足时说明实际证据和缺失条件，不将猜测写成事实。PR 分析说明现有 diff 与尚待完成的行为，不假设可以检出或执行不可信代码。不要重问已解决的问题。

据证据建议不同处理：范围外附已有决定及理由；重复附关联对象；信息不足只问影响判断的具体问题；可执行请求保留目标、验收与约束，可按需使用 [agent brief](references/agent-brief.md)。需要维护者作产品或取舍决定时，明确哪些问题需要人回答；技术事实可自主核查。对历史拒绝理由的复用见 [out-of-scope](references/out-of-scope.md)。

遵循项目既有角色、标签和迁移约定；缺少非必要标签不盲目创建或套用。按项目入口读取 tracker 配置及实际命令能力；需要配置时可使用 `setup-power-agent`，缺 tracker 不阻塞普通实现或审查。只读请求只报告建议。只有对具体 tracker 目标和操作有授权时才应用分类、认领、评论、创建或关闭；已有明确授权不需逐步重复询问。发布文字遵守项目披露要求，关闭或公开评论不因生成草稿自动获准。

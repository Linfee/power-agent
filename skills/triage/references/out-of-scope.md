# 历史拒绝理由

查项目已有的范围说明、ADR、tracker 决定和其他既有知识位置，以概念而非关键词匹配类似请求。指出当时实际决定、原因、来源和适用条件；历史拒绝不自动代表现在仍有效，维护者可确认、区分或重新考虑。

确有未来重复请求的消费者时，按项目现有知识位置记录简短的决定、持久理由和相关请求指针；遵守该位置的写入规则与授权。不默认创建另一套拒绝知识库，也不将普通暂缓或已经实现的请求记录为拒绝。说明已经实现时引用实际实现；对已改变的决定保留符合项目约定的历史，不擅自删除。

## 记录和复用

记录按概念而非请求逐条分散：同一决定的多个请求可以链接到一个既有知识条目。内容应让后来者理解决定本身、为什么、适用边界和来源，例如：

```markdown
# 深色主题

**决定：** 本项目不提供面向最终用户的主题切换。

## 理由
当前渲染与单一调色板绑定；支持运行时主题需要扩展配置与组件接口。
项目当前聚焦内容生成，嵌入方可自行处理展示主题。

## 相关请求
- <请求名称和链接>
- <另一个表达同一需求的请求名称和链接>
```

这是记录形状示例，不要求创建 `.out-of-scope/` 或覆盖项目现有文档协议。理由要能解释产品范围、技术约束或战略取舍；“现在太忙”一般说明延期，不等于永久拒绝。

新请求称为“夜间模式”时，也应能发现上面的深色主题决定。向维护者呈现“此前为什么拒绝、此次是否同一问题”，再按其决定处理：确认相同、认为相关但有区别，或改变原决定。决定改变时遵循项目历史记录方式更新而非擅自抹掉历史；是否重新打开旧请求另由维护者决定。所有 tracker 评论、关闭与知识写入各自受授权和项目规则约束。

# To Tickets

从已有目标、讨论和指定 issue 的正文及相关讨论出发，理解实际约束、术语与决定。仅当跨会话、调度或并行有收益时拆分，不为形式再造票。

优先切分可交付、可单独验收的端到端垂直切片，而不是按技术层拆成单独不能使用的半成品。每张票写清交付行为、局部验收、必要约束、父 spec/issue 指针和真正阻止开始的依赖；不把研究问题伪装成实现票。影响组合行为的集成工作及其依赖要明确，单票通过不自动证明整体完成。横跨全仓的机械迁移可按真实依赖分批，必要时用兼容的 expand–migrate–contract；不为形式强迫每批成为垂直功能，也不默认创建分支。

获准写入选定 tracker 时以稳定 ID 建关系。按项目配置和实际 CLI 版本、帮助及后端版本或 tier 确认支持的操作，不猜测命令；支持 native parent/blocking 时可用 native，否则在该 tracker 条目的固定正文位置记录。同一关系只选一种可更新真源。先创建依赖目标，再用实际 ID 建边；没有 blockers 的开放任务构成可调度 frontier。若后端是本地文件，遵守配置中的 Kind、State、Blocked by、Owner，外来请求的 Triage 是独立维度，不混作任务状态。

已有 tracker 沿用项目配置。只要求拆分方案或草稿、或缺少具体目标与操作的写入授权时，交付含依赖的草案，用票名或草案内标识引用尚未创建的票，明确标注未发布；用户要求发布但目标或授权无法确定时，只确认缺失部分，已有授权不逐票复问。缺配置时交付草案，并提示用户显式启动项目 tracker 配置。此流程以票据交付结束；即使原请求同时包含实施，也先交付票据，等用户下一步明确要求后再进入实现。父 spec 不因子票完成而自动关闭。

## 从目标切出可交付路径

先读指定材料的完整正文和相关评论，必要时查看现有代码、领域术语和相关 ADR；识别能够让后续修改更容易的准备性重构，但只有它确实解除后续工作障碍时才设为前置。每个 tracer bullet 应走通一条窄而完整的行为路径，涉及的持久化、接口、界面与证明都包含在该切片中；完成后能独立演示或验证，范围适合一个新的执行上下文。

例如要交付订单查询：

- 不佳：票 A 建数据库，票 B 写 API，票 C 写界面。任何一张完成后都无法证明用户能查到订单，且把层次顺序伪装成产品交付。
- 更好：先让用户按订单号查到一个订单（包含必要存储、接口、展示与测试），再增加按日期筛选；后者只在确实复用前者尚不存在的能力时依赖前者。另设必要的整体集成验收，覆盖筛选与查询组合。

每张票列出短标题、交付什么、可以单独验证的标准、父目标及真正阻止开始的票。依赖指“前者未完成，后者无法安全有效开始”，不是方便排序：可并行的票不必人为串成一条链。检查过粗的票能否切成各自有结果的行为，过细的票是否离开其他票就不能验证；需要用户决定交付范围或取舍时集中提出，明确的拆分不必逐票暂停。

横向迁移例外：例如共享字段改名，一次删除旧字段会同时破坏所有调用方，可能没有能独立保持通过的垂直切片。可先 **expand** 引入兼容的新字段，按包或目录分批迁移，每批依赖 expand；最后 **contract** 删除旧字段，依赖所有迁移批次。若批次各自无法保持可验证，明确最终集成与验证任务及其依赖，只在该组合点承诺整体通过；不要为迁移顺序虚构业务价值，也不要将临时兼容当永久接口。

## 票据草案

发布时沿用 tracker 配置；会话内草稿服从用户要的篇幅。最简票只写交付、验收和真实依赖，直接给票据。下面是可选结构，不是待填满的表单。验收来自父目标或现有契约；若边界行为尚未决定，把它留作问题，不替用户制定产品规则。

沿用上面的订单例子，用户只要最简草稿时，可以直接给：

- **草案 A · 按订单号查询**：输入已有订单号能看到对应订单。依赖：无。
- **草案 B · 按日期筛选**：在 A 的查询结果中只显示指定日期的订单。依赖：A 的查询能力。

这两条已经可以分别验收。不因为下面有第二个复选框，就自行规定“查无结果时必须弹窗”。同样，没有明确契约时，不把输入限制、保存时机或失败时的界面表现写成必须通过的条件。

```markdown
# <简短标题>

## 父目标
<spec / issue 的名称和稳定链接；没有则省略>

## 要交付什么
<用户可以完成或观察的端到端行为，以及必要约束>

## 验收
- [ ] <可独立判断的结果>
- [ ] <仅在已有要求或契约明确时，写对应的边界或失败结果>

## Blocked by
- <实际阻止开始的任务；已发布票据使用稳定 ID，草案使用名称或草案内标识；无则写 None>
```

本地记录另按配置填写 `Kind`、`State`、`Owner`；`Blocked by` 与状态独立。远程若使用原生依赖边，不再把正文列表作为另一可独立修改的关系源。创建时先取得真实 ID 再建立关系，不使用可能误链到其他 issue 的占位编号。描述以行为、接口契约和领域词汇为主，路径可能变化，除非有明确定位价值；确需引用原型中承载决定的精简状态机或类型时标明来源。

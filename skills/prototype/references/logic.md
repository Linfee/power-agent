# 逻辑原型

适用于状态转换、业务规则或数据模型中难以纸面判断的问题，例如“先取消再恢复，余额会怎样？”或“非法操作是否可能发生？”在原型可见位置用领域语言写下正在验证的问题，而非只放在代码注释中。

## 分离模型与展示

根据问题选择合适形式：离散事件可用 `(state, action) => state` reducer；合法动作本身是问题时可用显式状态机；数据变换可用纯函数；确实需要拥有持续状态时用接口清晰的模块。核心逻辑不引用 DOM、`document` 或按钮处理器，由展示层调用模型并渲染结果。纯函数或 reducer 易于移植，保留内部状态的模块则应明确初始化和外部依赖；不要为了原型预测未来扩展。

例如订单状态从 `draft` 经 `submit` 变为 `submitted`；`cancel` 后再 `submit` 应发生什么正是待验证问题。动作通过同一个模型入口执行，面板根据返回状态更新，而不是由按钮分别改写画面模拟结果。

## 可操作的演示

单文件 HTML/CSS/JS 可直接打开和分享，适合非开发者，不强制使用 HTML 或任何框架。无论采用何种载体，都让接收者容易运行，并提供：

1. 标题和一句话说明问题。
2. **当前状态面板**：用领域语言显示所有与判断有关的字段，动作后重新渲染；必要时指出刚发生的变化，避免只给非开发者一段原始 JSON。
3. **自由探索**：提供实际动作按钮，让人以任意顺序尝试；非法动作也应能看见其真实结果或被拒绝的原因。
4. **引导走查**：为典型路径、棘手边界和非法操作提供场景。每个场景说明起点、要观察什么和动作顺序；开始时重置到已知初始态，每一步都是执行真实模型动作的按钮，执行后更新面板并推进步骤，不是只展示预写结果。

例如“取消后重新提交”场景从新建草稿开始，依次点击提交、取消、重新提交，每一步观察订单状态与允许的动作；随后可自由尝试其他顺序。场景可以是标签页或适合宿主的其他形式，不以控件外形替代可重复操作。

## 交付与边界

实际运行关键路径，向用户交付运行入口、操作方法和观察；当用户发现“这不应该可能”时修改模型或补充场景，再记录最终观察的版本。需要保存决定依据时按主文保留准确可复查的原型。

默认内存状态，不连真实数据库；问题本身是持久性时才在授权内使用隔离存储。原型可帮助判断模型，但不能证明生产系统、外部服务或并发行为。正式实现获授权后，可借鉴已验证的模型逻辑，同时重新处理生产约束；演示外壳不直接作为生产代码。

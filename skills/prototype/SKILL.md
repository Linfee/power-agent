# Prototype

原型是**回答一个问题的可丢弃代码**。先说清问题、哪些观察会影响决定，以及运行与数据边界：

- 状态转换、业务规则或数据模型是否合理 → [逻辑原型](references/logic.md)：用可操作的状态面板、自由探索和关键场景检验。
- 页面应该长什么样、交互如何组织 → [界面原型](references/ui.md)：在接近真实的上下文中比较结构不同的方案。

两者都有关时分别验证各自问题。确实无法判断时，从用户描述和周边代码选择更可能的分支，并写明假设；不要求特定框架或固定数量的方案。

原型明确标记为可丢弃，尽量放在接近目标模块或页面、符合项目约定的位置，给出用户实际可运行的入口。默认用内存或安全的隔离数据，不连接生产写操作；只有问题本身涉及持久性且已获授权时才使用隔离存储。展示相关状态、真实画面或实际操作结果，而不只描述预期。省略与回答问题无关的生产级结构、测试和打磨，但保留安全边界与让原型可运行所需的处理。

如果画面有助于当前问题，用宿主现有展示与反馈方式；文字更清楚时无需画面。需要临时本地服务时限制访问范围、记录入口，并由启动者在结束后停止；不把临时内容公开。交付时指出如何启动、如何操作以及已观察结果的限制。

重要决定依赖原型时，清理前保存**实际观察的准确版本**及可复查指针，连同问题、场景、结果与限制保存在有消费者且获授权的位置；仅截图不能代替依赖交互或状态的原型。是否使用 Git 取决于实际保存需要及授权，不默认创建分支、提交或发布。原型回答问题后清理可丢弃部分；将结论用于正式实现需另有实施授权，演示不能充当生产实现或完整验收。

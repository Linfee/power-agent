# Prototype

先说清要回答的问题、观察什么会影响决定，以及原型的运行与数据边界。逻辑/状态问题用 [逻辑原型](references/logic.md)，视觉与交互比较用 [界面原型](references/ui.md)；两者都有关时分别验证各自问题。选择最小可运行形式，不要求特定框架或固定数量的方案。

原型明确标记为可丢弃；沿用项目约定，给出实际可运行的入口。默认用内存或安全的隔离数据，不连接生产写操作；只有问题本身涉及持久性且已获授权时才使用隔离存储。展示相关状态、真实画面或实际操作结果，而不只描述预期。演示只支持已观察的结论，不能充当生产实现或完整验收。

如果画面有助于当前问题，用宿主现有展示与反馈方式；文字更清楚时无需画面。需要临时本地服务时限制访问范围、记录入口，并由启动者在结束后停止；不把临时内容公开。重要决定依赖原型时，清理前保存**实际观察的准确版本**及可复查指针，连同问题、场景、结果与限制保存在有消费者且获授权的位置；仅截图不能代替依赖交互或状态的原型。是否使用 Git 取决于实际保存需要及授权，不默认创建分支、提交或发布。将结果用于正式实现需另有实施授权。

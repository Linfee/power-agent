# Prototype

原型是**回答一个问题的可丢弃代码**。先说清问题、哪些观察会影响决定，以及运行与数据边界：

- 状态转换、业务规则或数据模型是否合理 → [逻辑原型](references/logic.md)：用单文件 HTML 中的可操作状态面板、自由探索和关键场景检验。
- 页面应该长什么样、交互如何组织 → [界面原型](references/ui.md)：在同一路由上放 3 个（最多 5 个）结构不同的方案，用浮动切换栏比较。

两者都有关时分别验证各自问题。确实无法判断时，从用户描述和周边代码选择更可能的分支，并写明假设；逻辑分支用单文件 HTML，界面分支默认 3 个结构不同的方案。

原型明确标记为可丢弃，尽量放在接近目标模块或页面、符合项目约定的位置，给出用户实际可运行的入口。默认用内存或安全的隔离数据，不连接生产写操作；只有问题本身涉及持久性且已获授权时才使用隔离存储。展示相关状态、真实画面或实际操作结果，而不只描述预期。省略与回答问题无关的生产级结构、测试和打磨，但保留安全边界与让原型可运行所需的处理。

逻辑原型应能双击打开；界面原型在现有页面（优先）或明确标为 prototype 的临时路由中运行，并提供可分享、刷新后稳定的 `?variant=`。需要临时本地服务时限制访问范围、记录入口，并由启动者在结束后停止；不把临时内容公开。交付时指出如何启动、如何操作以及已观察结果的限制。

重要决定依赖原型时，把原型作为 **primary source** 捕获：在获得 Git 写授权时提交到 throwaway branch（不并入 main），并在实现 issue 上留下指向它的 context pointer；未获授权时保存完整可运行副本并记录可复查路径，不能直接丢弃。同时记录它回答的问题和结论。主分支只保留已验证的决定；将结论用于正式实现需另有实施授权，演示不能充当生产实现或完整验收。

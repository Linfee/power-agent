# Implement Spec

从指定 spec 和项目唯一 tracker 读取当前目标、票据、关系、所有权和必要讨论；已有完整 issue 直接交给 `implement`，不为使用本 Skill 额外造票。tracker 未配置时，只在确需持久任务图时按需使用 `setup-power-agent`；普通实现和审查不因此阻塞。协调者在运行中维护调度视图，不把它当第二个可独立更新的状态源。

把真正的 blocker 已完成、未被其他执行者占用的开放任务作为 ready frontier。核对当前状态后，按真实依赖和不相交的写所有权并行派发；共享文件或出口指定单一写者、串行处理或在明确授权的隔离环境中集成。每个子代理使用新上下文，给出目标、范围、共享契约、写入归属、验收、证据、允许和禁止动作及可信源指针。无固定并发上限；结果不完整或冲突时核实证据并补做，不能只汇总完成声明。依赖或目标变化后重新计算 frontier，独立工作继续。

**无 Git 隔离模式是完整路径**：仅一名协调者持有任务图和集成责任；子代理在当前工作区只写各自不相交范围，共享文件串行或交单一负责人。协调者检查实际工作树与交互，解决语义冲突后验证整体行为。不能擅自创建 branch/worktree、commit、merge、push、PR，或关闭任务、删除 worktree；这些都须已有明确授权覆盖具体目标和动作。确有授权且适合时可使用 Git 隔离，但不能把局部提交或合并冒充组合验收；保护已有未提交、未推送及他人工作，清理前核对归属和删除授权。

本地 tracker 的 `Kind`（spec/implementation/map/decision）、`State`（open/active/done）、`Blocked by` 和 `Owner` 分开，外来请求可另有 `Triage`。只有协调者写本地认领与完成状态，子代理返回结果；同图多会话若没有现成可靠原子认领机制则串行协调。远程 assignee 或写唯一标记后重读不是原子锁；遇竞争先重新核对，不能假定独占。状态写入、认领、评论及关闭都须分别获得覆盖实际目标的授权，实施许可不等于 tracker 写入许可。

每个切片按 `proof-oriented-development` 获取与行为匹配的证据，适用时由 `code-review` 检查需求与工程两维并修复。协调者复用仍有效的证据，对共享接口、集成点和完整 spec 做组合验收；必要时检查 staged、unstaged 与新文件，不能将子票全完成等同整体满足。只在代码、证明和整体范围相符且获得写授权时更新相应状态；父 spec 不因子票完成自动关闭。报告实际完成、证据和缺口；未经授权的发布或状态回写单独说明，不伪称已执行。

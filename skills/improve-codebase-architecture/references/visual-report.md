# 可选架构图示

当调用关系、数据流或前后结构用图比文字更容易理解时使用，不强制 HTML 或图片。以实际文件、调用方向和复杂度位置为依据；图是解释，不是收益的证据。

## 候选展示

每个有价值的候选可包含：标题、涉及文件及消费者、当前问题、建议变化、具体收益与代价、前后对照，以及推荐强度（例如强烈建议、值得探索、证据不足）。有冲突的 ADR 要注明具体编号和为何真实摩擦值得重新讨论。最后指出最推荐先探索的候选与原因，避免把“更整洁”当作理由。

例如：

```text
当前：入口 A ─┐
      入口 B ─┼─> 校验 → 定价 → 保存（各入口各自协调顺序）
      入口 C ─┘
建议：入口 A/B/C → 订单提交模块 [校验、定价、保存]
待确认：不同入口的失败处理是否一致？集中后依赖与测试如何变化？
```

图中把拟议结构标为建议，而不是已存在；如有漏出的调用或不同失败语义应修正，不要让简化图掩盖代价。

## 选图

- **依赖/调用图**：节点为真实模块，箭头表示实际依赖或调用，适合看跨 seam 的泄漏。
- **顺序图**：按时间画调用与返回，适合比较多次往返、事务或错误处理。
- **层次截面**：把调用穿过的薄层画成横带，对照可能集中到同一职责的部分；保留仍有意义的资源和权限边界。
- **接口与实现面积对比**：并列表示调用方必须理解的接口与内部实现，帮助讨论浅模块和深模块，不把视觉面积当作度量。
- **调用树折叠**：展示多个散落的内部调用如何被一个行为接口封装，同时保留真正对外可观察的结果。

一种 HTML 报告可用标题和图例（模块、seam、泄漏、深模块），候选卡片中并排展示前后图，再给文件、问题、方案、收益、代价和不确定性；最后放推荐项。图形可用文本、Mermaid、内联 SVG 或简单盒线，选与关系匹配的形式，而不是每项都套同一种图。图例应解释符号，颜色不能是唯一信息，文字要在图无法渲染时仍可读。

图片、文本或自包含 HTML 均可；必要信息离线仍可阅读，不依赖固定 CDN。若生成临时报告，告知路径及处置方式；不要将敏感代码或图发布至外部服务。

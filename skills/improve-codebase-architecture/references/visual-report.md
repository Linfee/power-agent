# 架构候选报告

探索完成后生成一个自包含 HTML 报告，写入系统临时目录并打开；报告用于快速比较候选，不是实施授权，也不在这一步提出接口设计。

## 结构

- **总结**：范围、主要摩擦、最重要的候选和推荐先探索的一项。
- **候选卡片**：标题、涉及文件与消费者、当前问题、建议变化、具体收益与代价、前后对照、推荐强度（例如强烈建议 / 值得探索 / 证据不足）。有冲突的 ADR 注明编号和重新讨论的理由。
- **图示**：依赖或调用图、顺序图、层次截面、接口与实现面积对比、调用树折叠，按关系选择；图例解释符号。
- **不确定性**：证据不足、未验证的假设和仍需讨论的约束。

以实际文件、调用方向和复杂度位置为依据；图是解释，不是收益的证据。拟议结构标为“建议”，不要画成已存在；有漏出的调用或不同失败语义应修正，不要让简化图掩盖代价。

例如：

```text
当前：入口 A ─┐
      入口 B ─┼─> 校验 → 定价 → 保存（各入口各自协调顺序）
      入口 C ─┘
建议：入口 A/B/C → 订单提交模块 [校验、定价、保存]
待确认：不同入口的失败处理是否一致？集中后依赖与测试如何变化？
```

## 实现

用 Tailwind 与 Mermaid 的 CDN 版本快速排版和画图；也可用内联 SVG 或简单盒线。图把拟议结构标为“建议”，文字在图无法渲染时仍可读，颜色不是唯一信息。敏感代码和调用细节留在本地，不上传外部服务。

报告生成后告知绝对路径及处置方式；临时报告不进入仓库，除非用户要求保留。

# 维护长期开发知识

按真实读者和使用时机保存未来会复用的系统事实、边界、开发方式与决策理由；也核对已有文档是否仍成立。沿用项目既有布局和协议，优先修订已有正文；不因为安装 Skill 要求普通文档变成 Bundle 或预建知识树。局部显然的实现细节由代码与测试表达。

## 判断范围

- 该写：稳定的系统事实、模块边界、不变量、公开契约、开发与运行方式、集成参考、决策理由。
- 不该写：README 式介绍、会话记录、执行计划、任务状态、临时调试结论；这些留在对应真源。
- 先核对变化事实、来源、适用范围与读者用途，区分当前事实、假设、历史决定和任务状态。研究、原型和执行轨迹不自动成为长期事实。
- 术语和决定是否值得记录由 `domain-modeling` 判断；沿用已有 glossary/CONTEXT 与 ADR，不创建第二份权威。

## 写入或修订

- 沿用项目现有布局、命名、语言和文档协议；优先修订已有权威正文，不新建同义文档。
- 需要新文件时放在真实消费者能找到的位置；没有约定且确有知识要保存时，按项目已有结构选择，不预建目录树。
- 采用 Power Bundle 时，按[项目 Profile](references/project-docs-profile.md)处理 Concept、索引及 ADR 元数据；完整格式按需查[唯一 OKF 参考](references/okf-v0.1.md)。保留未知字段和类型，不因模板缺项而清除。
- 敏感资料、密钥、个人或客户标识、私有 URL query 和原始日志不进入正文、示例或引用；使用脱敏事实与可访问的稳定来源，无法核实时明确保留未确认状态。
- 移动、重命名、拆分、合并或删除文档需要实际理由和授权；修复受影响入链，导航变化时更新入口。
- 已接受决定保留历史；授权重开时记录新决定与替代关系，不从代码反推决定已获批。

## 核验

- 读取支撑声明的代码、测试、配置、Schema、生成源、ADR 和相关链接；按需扩大证据，核对关键声明、范围与引用。
- 结构检查、链接存在、修改时间或命令已准备好，都不能替代语义证明；文档年龄和 Git diff 只提示候选。
- 证据冲突、来源不可访问或边界不清时保留未验证面，不把推断写成事实；“已检查”或“已更新”不等于内容正确。
- 用户要求仅凭文档完成任务，或已知存在误读时，以不继承当前解释的新上下文执行代表性消费任务；报告实际验证与未核实部分。
- 修复无争议的当前事实、命令、链接和来源路径后重新核对；仅做格式修改不等于完成验证。

## 完成

报告实际修改、逐项核验的来源、验证方式和未覆盖部分；不复制执行进度，不把任务状态写进长期知识。证据已覆盖当前内容后结束。

# 补充领域知识与导航

先定位项目现有 glossary、`CONTEXT.md`、跨 context 地图和相关 ADR，入口只指向真实存在且与任务相关的资料。沿用项目术语与已有决定；发现冲突要说明，不凭当前代码覆盖历史。没有相关知识时不预建空文件。

需要新增或澄清术语、关系、跨 context 地图或记录决定理由时，按需读取 `domain-modeling`；它负责术语与决定语义。复用已有 CONTEXT，确无约定才采用其默认 glossary；仅存在真实跨域导航需求时增加地图，不按目录数或服务数推断 context。需要把成果写入已采用 Bundle 的 `docs/` 时，使用 `dev-docs` 的项目 profile；Bundle 外文件不机械添加元数据。

项目入口可简短说明领域资料在哪里、何时读取、如何处理 ADR 冲突；按实际路径调整，不复制成第二份知识正文。

# 补充领域知识与导航

先定位项目现有 glossary、`CONTEXT.md`、跨 context 地图和相关 ADR，入口只指向真实存在且与任务相关的资料。沿用项目术语与已有决定；发现冲突要说明，不凭当前代码覆盖历史。没有相关知识时不预建空文件。

生成的消费指针要让实际接手工作的 Agent 知道：

1. 探索相关代码或提出方案前，读取项目现有词汇表或 CONTEXT；有上下文地图时先通过地图找到本次任务涉及的资料。再读取涉及该区域的系统级和上下文级 ADR，而不是假定所有决定都在根目录。
2. 在 issue 标题、设计提案、假设和测试名中沿用相应上下文的首选词；遇到词汇表明确避免的同义词时使用项目用语。找不到概念时，先确认是否用了项目外术语；确是领域缺口则记录待澄清，不自行编造定义。
3. 方案与已有 ADR 冲突时明确指出具体决定及冲突，例如“与 ADR-0007 的事件溯源决定冲突，原因是……”。是否重开决定由已有授权和决策流程确定；不能静默覆盖或根据当前代码推断历史决定已失效。

缺少某个文件时继续处理当前任务，不因模板要求提示用户先创建空词汇表或 ADR。只有真实术语、关系或决定形成并有授权时才记录；具体选择与格式由下方既有职责决定。

需要新增或澄清术语、关系、跨 context 地图或记录决定理由时，按需读取 `domain-modeling`；它负责术语与决定语义。复用已有 CONTEXT，确无约定才采用其默认 glossary；仅存在真实跨域导航需求时增加地图，不按目录数或服务数推断 context。需要把成果写入已采用 Bundle 的 `docs/` 时，使用 `dev-docs` 的项目 profile；Bundle 外文件不机械添加元数据。

项目入口可简短说明领域资料在哪里、何时读取、如何处理 ADR 冲突；按实际路径调整，不复制成第二份知识正文。

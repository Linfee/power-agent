# 领域资料指针 seed

只在现有入口缺少可用路由时使用；将此指针改写为项目实际存在的路径，而非照搬示例。说明项目词汇表或 `CONTEXT.md`、必要的跨 context 地图及相关 ADR 在哪里，以及什么任务需要读取。使用项目首选术语；输出与已有决定冲突时明确指出，不静默覆盖。资料不存在就按实际任务继续，不为满足模板创建空 glossary 或 ADR。具体术语和决定语义由 `domain-modeling` 管理，Bundle 写入按 `dev-docs` profile。

例如，按项目实际资料改写后可生成：

```md
# 领域资料

- 涉及 <业务范围> 的代码或方案时，先读 <词汇表或 CONTEXT 的实际路径>。
  如有上下文地图 <实际路径>，从中找到本任务涉及的领域资料。
- 查阅 <系统级 ADR 路径> 和 <相关上下文 ADR 路径> 中与任务有关的决定。
- 在 issue、测试和设计中沿用项目首选术语；遇到缺失的概念先核对是否为
  项目外用语，确有缺口时记录待澄清。
- 提议与已有 ADR 冲突时指出具体 ADR、冲突与理由；不静默覆盖。
```

不存在的路径和不适用的分支删除；若已有消费说明，补充到原处而不是创建第二份。领域指针如何定位相关资料与处理缺口，参见 [领域资料导航](domain-docs.md)。

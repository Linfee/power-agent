# 补齐最小入口与项目知识

让当前宿主能找到已有知识，并补齐完成真实任务所缺的必要内容。沿用项目结构；整体导航的设计与历史反馈演进是另一类目标，本 Skill 不将局部初始化扩大为体系重建。

## 确定实际缺口

从宿主、现有入口及加载关系选择编辑位置。入口缺失且宿主已知时按其约定创建；多个入口保留真实加载关系，不重复维护正文。只有权威来源、目标或风险存在实质歧义时才询问，已授权的可逆补缺口直接完成。

检查后续 Agent 能否定位所需构建、测试、系统或领域资料，优先补引用和现有正文。目录随真实内容建立，不预建固定骨架、空 ADR 或 CONTEXT 文件。需要补充领域表达时读 [项目记忆](references/domain-docs.md)，需要记录真实决策时读 [ADR 格式](references/adr-format.md)。

## 保持契约

- 保留用户已有编辑，就地更新相关内容；术语沿用权威领域文档，与既有 ADR 冲突时显式说明，不重写历史结论。
- Bundle 内 Concept 遵守项目元数据契约，YAML `type` 非空；Bundle 外的宿主入口与 CONTEXT 文档不机械添加 frontmatter。
- `timestamp` 只表示语义变化。验证状态属于受控工具维护的 ledger，初始化不手工登记或伪造验证历史。
- 迁移、删除、外部操作及全局配置仍按用户目标与授权处理，局部初始化不扩大权限。

## 验收

核对实际加载链、每个新增导航目标及关键声明的代码或配置来源；新增或修改的 Concept 符合元数据契约。构建、测试说明用能直接覆盖其内容且成本相称的检查验证，无法执行时说明未验证面。交付实际修改、已运行检查与剩余缺口，文件数量不作为完成条件。

本 Skill 可独立完成最小补缺口。持续语义写入可按需使用 `dev-docs`，既有 Bundle 的扫描、结构维护或登记可使用 `dev-docs-maintain`，不形成固定前后置链。

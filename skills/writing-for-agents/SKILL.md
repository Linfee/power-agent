# 为 Agent 写作

适用于任何由 Agent 读取的文档：Skill、`AGENTS.md` / `CLAUDE.md`、被指针引用的文档。包装不同，写法相同：同一套杠杆让每次运行的过程可预测，而不是让输出一致。

写 Skill 时，另读 [Skill 调用机制](references/skill-mechanics.md)，了解 frontmatter、调用方式与 router skill。

## 上下文指针

**上下文指针**是留在 Agent 上下文里的引用：它指出某个不在上下文中的材料，并写明到达它的条件。Skill 的 description 是一个指针，`AGENTS.md` 里点名某文档的一行也是同一个东西。决定 Agent 何时、多可靠地到达材料的，是指针的**措辞**，不是目标。必需材料挂在措辞薄弱的指针后面，是方差 bug：先磨尖措辞；磨不动时再内联。

指针做两件事：说明材料是什么，列出应触发读取的**分支**（分支是文档处理的不同情况，不同运行会走不同路径）。常驻指针的每个词每轮都付费，所以要比正文更狠地精简：

- **前置引导词**：指针是引导词真正发挥作用的位置。
- **每个分支一个触发词**。给同一分支换同义词，等于把同一分支写两遍；合并它们，只留真正不同的分支。
- **删掉正文已经承担的身份介绍。**

## 两种负载

每份文档和指针都花掉两种预算之一：

- **上下文负载**：常驻材料占用 Agent 窗口的成本。`AGENTS.md` 的一行、skill description、每轮都在上下文里的内容，无论是否触发都消耗 token 和注意力。
- **认知负载**：人记住有哪些文档、何时该用哪份的成本。人就是索引。它不是要最小化的成本，而是人的能动性的价格；人的判断重要处值得花，不重要处应移除。

只通过指针到达的材料，用指针自身一行换掉了上下文负载；完全没有指针的材料，则完全压在认知负载上。

## 信息层级

文档由两类内容组成：**步骤**（Agent 按顺序执行的动作）和**参考**（按需查阅的定义、规则、事实）。两者可自由混合：全步骤（配方）、全参考（审查规则、本 skill）或两者兼有。核心决定是每块内容放在**信息层级**的哪一级：

1. **文件内步骤**：主要层级，Agent 按顺序做什么。
2. **文件内参考**：按需查阅。经常是合法的平级集合（一次审查的全部规则放同一级），这是可接受的安排，不是异味。
3. **披露参考**：推到独立文件，由上下文指针到达，只在指针触发时加载。范围从同目录的兄弟文件，到任何文档都能指向的外部参考。

下沉太少，顶部膨胀；下沉太多，把 Agent 真正需要的材料藏起来。这个张力就是全部决定。

**渐进披露**是沿层级向下移动（移出主文件、放到指针后），让顶部保持可读。它主要不是 token 优化，而是保护层级的方式。分支是最干净的披露测试：每个分支都需要的内联，只有某些分支到达的放到指针后。文档有步骤时，本该披露的文件内参考会埋掉步骤，让关注步骤变成抛硬币：这是方差杠杆，不只是可读性问题。

**就近放置**是文件内的配套：层级决定一块内容放多深，就近决定它旁边放什么。把一个概念的定义、规则和例外放在同一标题下，而不是散落各处，读一部分就会带出邻居。检验标准：文档读起来应像为 Agent 写的文档。分组材料如此，散落材料不然。（它与重复不同：重复是在两处写同一意思；散落是把一个意思碎到多处。）

**蔓延**是这里的失败模式：文档就是太长，即使每行都有效且唯一。注意力在多余部分变薄，每一行都是需要保持相关的额外负担。解药是层级：把参考披露到指针后，按分支或顺序拆分，让每条路径只携带自己需要的内容。

## 步骤与完成条件

每个步骤都结束于**完成条件**：告诉 Agent 工作已完成的判据。两个属性使它成为杠杆：

- **清晰度**：Agent 能否区分完成与未完成？模糊边界（“理解已经达成”）会招来**提前完成**：步骤真正结束前就收尾，注意力滑向“已经做完”。前方可见的步骤（**完成后步骤**）提供拉力，完成条件的清晰度是阻力。按顺序防御：先磨尖边界（局部且便宜）；只有在边界不可约地模糊、且确实观察到抢跑时，才通过拆分序列藏起后续步骤。隐藏只在真实上下文边界上有效（交接或 subagent 派发；内联调用仍把后续步骤留在上下文里，什么也没清掉）。
- **要求范围**：它要求多少工作。“每个被修改的模型都已交代”迫使彻底工作，“列一份变更清单”不会。要求范围驱动 **legwork**（Agent 在工作内做的挖掘，隐含在措辞里，而不是写成单独步骤），且不限于步骤：“每条规则都已应用”约束一组平铺参考，正如“每个步骤都完成”约束一个序列；这就是全参考文档仍能带有穷尽性门槛的原因。

最强的完成条件既可检查又穷尽。

## 何时拆分

把一份文档拆成两份会花掉两种负载之一，所以只有切分值得时才拆：

- **按顺序**：当后续步骤会诱使 Agent 赶完眼前步骤时，拆开这段序列。让后续步骤不在视野内，会驱动当前任务上更多 legwork。注意反面：合并序列会把每个步骤的后续暴露给接下来，招来提前完成。
- **按调用方式**：Skill 特有，见 [Skill 调用机制](references/skill-mechanics.md)。

## 引导词

**引导词**是模型预训练中已有的紧凑概念，Agent 在运行文档时用它思考（*lesson*、*fog of war*、*tracer bullets*）。它作为 token 反复出现，而不是作为句子重复，于是积累出分布式定义，用最少 token 锚定一大片行为，靠的是调动模型已有的先验。自造词只要定义清楚也能用，但造词不调动先验：预训练词免费给你的东西，你要用定义 token 付账；优先找现成的词。

它在两处锚定。在正文里锚定**执行**：词一出现，Agent 就取用同一行为；在平铺参考里，它把注意力聚焦到某一类要寻找的东西。在指针里锚定**调用**：同一个词同时活在提示词、文档和代码库里时，Agent 把共享语言与材料连起来，更可靠地到达它。

主动寻找用引导词重构的机会。三处拼写的三元组、花一句话比划一个概念的指针，都是等着折叠成单个 token 的段落：

- “快、确定、低开销” → **紧**（紧反馈环）。
- “你信得过的环” → **红**，把模糊门槛变成二元可观察状态（环在 bug 上变红，或者没有）。

你赢两次：更少 token，以及更锋利的挂钩让 Agent 挂住思考。假设每份文档都带着能被引导词退休的复述。去找出来。

**否定**是这把杠杆旁边的失败模式：用禁止来驾驶，会把被禁行为拖进上下文，让它更可用，而不是更不可用。*不要想大象*，大象就占满一切；否定是弱修饰语，被强激活的概念淹没，于是禁令有一半读起来像“去做那件事”的指令。提示**正面**：说出目标行为（“写单行注释”），被禁行为就从未被说出口。禁止只有在无法用正面表述时，才作为硬护栏保留；即便如此，也要配上正面目标，让注意力落在该做什么上。

## 精简

- 每个意思放在**单一真源**：一个权威位置，改变行为就是改一处。**重复**（同一意思出现在多处）带来维护和 token 成本，并把一个意思在层级上的显眼程度抬过它真实的等级。（它是引导词的意外反面：引导词故意重复 token，从不重复意思。）
- **环境**也是真源（`package.json` scripts、配置文件、目录布局、`--help` 输出），复述环境的文档是**缓存**：一次查找的副本，只有查找昂贵时才值得这份负载。缓存 Agent 靠看找不到的东西：未写下的约定、选择背后的理由、没有任何配置会承认的坑。把单文件、单命令就能查到的留给环境，那里不会过期。
- 逐行检查**相关性**：它还与文档要做的事有关吗？一行失去相关性，可能因为从不与任务相关（纯说明，或本应披露的分支），也可能因为它描述的行为或世界变了而过时。更短的文档更容易保持相关。没有精简纪律，默认命运是**沉积**：过时层一层层落下，因为添加感觉安全、删除感觉冒险，直到你必须打钻穿过它们，才能找到还活着的东西。
- 逐句猎捕 **no-op**：模型默认就会遵守的指令，花负载说了等于没说。检验（它是否改变行为，相对于默认？）是相对模型而非相对读者的：两个人对 no-op 的判断不一致，其实是对默认行为判断不一致；用运行文档来裁决，不要辩论。一句话不合格时，整句删掉，而不是修剪词语。这个检验也评级引导词：一个弱到打不过默认的词（Agent 已经比较彻底时还说“要彻底”）是 no-op，修法是换更强的词（“不留死角”），不是换一种技巧。

修改后检查受影响的正文、链接、示例与直接消费者。结构检查只能发现路径和元数据问题，不能证明 Agent 会正确行动；需要判断精简、发现性或行为变化时，用相同任务、模型、宿主、工具和授权比较实际结果与整条路径成本。可选的文本取舍与行为对照判据见 [按需判据](references/criteria.md)。

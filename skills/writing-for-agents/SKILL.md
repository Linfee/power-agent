# Writing for Agents

为 Agent 写作时，先确定读者要完成的目标，以及现有材料缺少哪些会改变行动、判断或验收的信息。修改时读取受影响的正文、引用和直接消费者；用户目标、授权和项目现有契约决定边界。不要为统一格式增加流程。

## 指针与内容

- 指针说明材料解决什么问题、什么情况下读取，并指向实际可达的位置。description、项目入口中的导航和正文引用都承担这一作用；区分不同场景，删掉重复同义词和身份介绍。
- 入口保留完成常见任务必需的判断、授权和完成条件；只有部分场景需要的细节放在带明确触发条件的 reference。不要把必需边界藏在没有有效指针的文件里。比较整条实际阅读路径的成本，而不只是主文件长短。
- 将相关规则、例外和操作放在一起；复用权威来源，避免把可从项目配置或命令直接查到的事实复制成易过期的缓存。写明可观察的完成条件和相应证据，不靠口号或固定步骤代替判断。
- 删除不改变行动、边界或验收的文字，同一消费路径内合并重复；但保留安全、授权和机器协议。某句是否只是模型默认行为，应通过当前模型与宿主的实际表现判断，不能仅凭直觉。机械、重复且可确定裁决的约束优先放在真实可运行的检查中。

## 写 Skill

Skill 需要明确用户目标与行为缺口；description 用用户实际会说的场景表达触发条件，保持简短而可区分。正文提供达成目标所需判断，避免强加固定报告、人工停顿或无关流水线。拆分看是否有不同的实际消费需要；合并要保留各自验收。整包可按需具名调用其他 Skill 或读取其权威 reference，不承诺单独安装仍完整；依赖和触发条件必须清楚、安装后可达。按需查阅 [Skill 调用与发现](references/skill-mechanics.md)。

检查修改涉及的正文、链接、示例与直接消费者。结构检查能发现路径和元数据问题，但不能证明 Agent 会正确行动；需要判断精简、发现性或行为变化时，以相同任务、模型、宿主、工具和授权比较实际结果与整条路径成本。不要把规则复述当作行为证据，或把未经验证的措辞、注意力和提前完成机制写成事实。文本取舍与行为对照细节见 [按需判据](references/criteria.md)。

# Skill 调用机制

这是 `writing-for-agents` 的 Skill 专用分支：frontmatter、调用方式与 router skill。其余写法见 [主文件](../SKILL.md)。

## 调用方式

两种选择，交换两种负载：

- **模型可调用**的 Skill 需要能区分适用场景的 `description`，让模型和其他自动能力找到它；人也可以点名。多个流程都需要且应允许自动触发的参考，可放在这里。常见写法是省略 `disable-model-invocation`。
- **仅手动调用**的 Skill 仍有面向人的简短 description，供显式入口展示。约束是不让模型自行启动，并非保证宿主隐藏名称或完全不占上下文。按宿主声明手动调用策略，见下文；其他 Skill 不得读取它的正文绕开限制。

当 Agent 必须自行到达该 Skill，或其他 Skill 要调用它时，才提供自动入口。只有人在决定工作方向后才应启动的流程，保留显式入口即可。

两个手动入口都需要的共享材料可放在独立的普通 reference，由各入口按需引用；共享的是参考资料，不是对另一个手动流程的调用。

## 按调用方式拆分

拆分的调用切分（顺序切分在主文件）：当你有一个应当独立触发它的独特引导词（你实际会在提示词里用的触发词），或其他 Skill 必须到达它时，拆出一个模型可调用 Skill。你要为新的常驻 description 付上下文负载，所以独立可达性必须值这个价。

## Router skill

当手动入口多到记不住时，**router skill** 可以按情境向用户介绍已有入口。它只帮助用户选择，不能代替用户启动手动流程。

不同宿主的开关与发现行为可能不同（例如 Codex 的 `agents/openai.yaml`），以目标宿主和版本为准，不把元数据当通用访问控制。名称、描述或调用方式变化时同步项目入口与直接消费者，分别验证模型发现、用户显式调用和依赖可达性。

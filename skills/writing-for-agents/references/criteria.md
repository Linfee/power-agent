# Agent 文本维护的按需判据

用于取舍文本、检查调用与对照行为；不是每次修改都要逐项执行的清单。

## 文本诊断

| 观察 | 处理 |
|---|---|
| 句子不改变行动、边界或验收 | 删除；将必要的模糊要求改成具体结果 |
| 同一消费路径反复解释同一规则 | 集中表达，保留改变选择的例外 |
| 入口包含少数场景的长细节 | 下沉为 reference，说明何时读取 |
| 规则只覆盖旧任务或旧宿主 | 核对实际消费者后修订或删除；历史记录不当当前指令 |
| 禁令缺少可行行动 | 补充最短替代动作；安全禁止不必为文风改弱 |

例如，多处重复“已有授权不必再问”，可集中在动作发生处：“核对既有授权覆盖目标与操作；目标、范围或风险实质变化才重新确认。”

引用未被读到时，检查实际加载路径、触发提示与内容是否必需；可改指针、内联短边界或重组。比较实际消费路径的总成本。整包具名调用可保留共享知识的单一权威，但依赖必须在安装后可达；不承诺独立安装，也不为去重增加无用的交接链。切分看消费目标和验收，合并看能否保住各自的完成条件。

## 调用方式

用用户实际会说的场景区分 description，避免身份介绍、流程说明和同义词堆叠。长度按目标仓库的检查契约；字符或估算 token 不能代替实际上下文用量。

Power-Agent 除 `grill-with-docs` 按 Matt 原版手动调用外，其余目标入口允许模型调用。其他宿主和项目的调用开关、发现与上下文行为可能不同；具体区分见 [Skill 调用与发现](skill-mechanics.md)。改名、触发或调用方式变化时核对 frontmatter、宿主元数据、仓库索引和直接消费者。不要把“被点名次数增加”当成任务质量改善。

## 行为对照

需要判断精简、拆分或发现性是否有效时，选择能暴露相关错误的代表性任务，在新会话与隔离工作区比较。可比较基础环境、当前版本与候选版本；保持模型、工具、授权、输入与验收一致，记录无法隔离的系统指令或宿主差异。

验收取自用户结果与真实契约：任务是否完成、关键行为是否正确、有无越权或未授权数据损失。阅读量、提问、工具调用、重复验证和耗时用于解释成本，不要求固定流程或调用次数。结构检查只能证明结构，复述规则只能证明能复述。

优先复用已定位的失败场景，不为每次文字修订运行整套评测：

| 场景 | 可观察验收 |
|---|---|
| 只要计划，且有生成与消费依赖 | 交付所需计划并保留必要顺序；不改实现 |
| 只要建议或内联可视化讨论 | 交付结论，不额外写 spec 或启动无关服务 |
| 调查暂缺区分证据，但有可用探针 | 继续取证到可支持的结论；保留获授权的安全材料，停止临时运行 |
| 从其他工作目录调用 Skill 脚本 | 操作明确的目标仓库；空格路径有效，目标切换失败不回落旧仓 |

验证发现性时，给自然请求与实际可见的目录，不先点名答案；记录未加载、加载哪些正文和任务结果。显式调用、目录辅助选择与宿主原生发现分别报告；未读到某正文的样本不能验证其内容，短任务直接完成也不等于漏调用。

保留可复查的任务输入、版本、执行轨迹与结果，不收集秘密或超出授权的历史。样本少时报告观察，结果混杂时增加针对性样本；不从一次顺利运行声称普遍提升，也不为每次文字编辑自动启动评测平台。

“某个词更能锚定注意力”“后续步骤导致提前完成”等解释是待验证假设。出现提前完成时，区分验收不清、证据缺失、授权误判、引用不可达和上下文负担，再选择修复；不要把一种心理机制写成通用事实。

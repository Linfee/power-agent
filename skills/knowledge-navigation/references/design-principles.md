# 知识导航的设计判据

本页用于结构取舍。以下方法是设计启发，不是统一目录标准、通用层数上限或应当全部实现的功能清单。

## 任务与知识单元

用真实问题确定覆盖范围：未来 Agent 要作出什么判断，缺少哪项知识会找错位置、误解契约或漏掉验证？稳定而难从代码恢复的边界、术语、决策理由优先组织；可直接查询的符号、目录和机器状态优先复用工具或生成源。

共同使用、共同变化的内容放近。拆分应能让独立任务少读无关内容，或分别维护不同版本、所有者和失效条件；两篇文档总要一起读才能理解时考虑合并。最小单元仍须保留完成其问题所需的前提、结论和边界，不能为了短而丢失语义。

用途区分可以借鉴教程、操作指南、参考和解释：教程支持学习，操作指南支持已知目标，参考提供精确事实，解释保存理由。这些角色可以在现有目录中表达，不据此预建四套目录。

## 入口与关系

实际加载的 Agent 入口保留跨任务关键边界和任务路由。摘要应帮助选择：覆盖什么问题、适用于哪里、下一处能得到什么。链接标签使用任务语言和稳定术语，必要时登记仓名、运行时名与历史别名的映射。

三种关系分别表达：导航说明去哪里；依赖说明理解或执行前需要什么；引用说明何种证据支持当前断言。用自然语言说明关系，普通 Markdown 足够时不引入额外边类型或图数据库。必要前提避免循环必读；相关主题之间的双向链接本身不是错误。

每个事实有一个明确的权威正文；不同索引可以指向它。为可发现性保留的短摘要、别名或跨任务护栏可以重复，但它们不能成为第二处手工维护的完整规范。

## 深度与复杂度

| 观察维度 | 决策依据 |
|---|---|
| 导航选择次数 | 常见任务尽量少次选择到正文；1–3 次可作起点，不能成为所有项目的硬门禁，证据核对另计 |
| 单页分支 | 入口能否明确区分候选；按任务分组优先于增加空中间层 |
| 实际读取量 | 比较找到充分知识前读入的相关与无关内容；单文件行数不代表总成本 |
| 前置依赖 | 必需前提是否在近处，是否存在必须层层补读才能行动的链 |
| 维护耦合 | 一个事实变化需要手工改几处、谁负责同步、哪些视图可生成 |

新增一层应减少实际选择困难；只有“继续阅读下一页”的中间索引通常可以移除。知识小而集中时保持平面布局；主题多且有独立消费任务时再分层。已知目标可以搜索或直达，归属不明再走地图，根入口不强制所有任务从头遍历。

每个新增字段、索引、检查器或登记机制，都应有当前消费者、维护方式和撤除条件。现有文件与工具能够满足目标时先复用；检索、失效传播或多人维护的实际瓶颈再支持更强机制。

## 事实与适用范围

按内容需要回答：断言描述哪个对象、适用于什么版本或环境、依据是什么、什么变化会使它失效。设计要求、代码实现和部署事实有不同权威；先定位冲突类型，不设置“代码永远覆盖需求”或“新文档永远覆盖运行态”的总排序。

来源引用应支持相应声明，路径存在只证明可定位。历史快照保留时间、适用范围与替代入口；源变化是核对触发器，不直接证明结论变错。内容时间与验证时间分别维护，hash 未变不证明绝对正确。

知识维护沿用项目协议：新知识在真实可复用时沉淀，正文有语义变化时更新必要元数据；结构变化修入链和索引。自动生成视图和验证登记通过其权威工具处理，不能手工刷新派生状态。

## 来源与证据限度

- [OpenAI Harness Engineering](https://openai.com/index/harness-engineering/)：短入口与仓库知识地图的工程实践。
- [Anthropic Context Engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)：按需探索与预加载之间的成本取舍。
- [Diátaxis](https://www.diataxis.fr/start-here/)：按读者需要区分文档用途。
- [Evaluating AGENTS.md](https://arxiv.org/abs/2602.11988) 与 [On the Impact of AGENTS.md Files](https://arxiv.org/abs/2601.20404)：不同实验得到不同效果，结构建议须在目标模型、任务和仓库中验证。

这些资料提供设计依据，不授权外部操作，也不构成每次运行都需阅读的前置链。本文的具体结构取舍仍由当前项目证据决定。

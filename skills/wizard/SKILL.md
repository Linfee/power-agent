# Wizard

向导把确需人操作、输入或批准的步骤拆成能逐项完成的引导；不把 Agent 已获授权且可安全完成的普通工作推给人。生成向导不等于执行它或授权其副作用。

## 确定范围和信息来源

先检查项目现状，分清目标、当前状态、依赖顺序和哪些步骤必须由人完成。例如从 README、示例配置、部署文件和 CI workflow 的变量名确定需要哪些值；不要读取已有秘密当作默认值。迁移则识别当前状态、目标状态及不可逆步骤。对每个输入记下：从哪里取得、是公开值还是秘密、用于什么、写入哪里或根本不写入。按实际需要给用户简洁阶段清单；若存在会改变范围或目的地的未决选择，先确认，不让已解决的细节阻塞安全本地工作。

逐阶段核实人要走的路径、当前界面标签或命令：以实际界面、当前官方文档及目标项目配置为来源，记录必要版本或日期。比如已核实的路径才写成“控制台 → 开发者设置 → 测试密钥 → 复制”，并说明该值的用途；界面不可确认时明确说明缺口，请用户补足或自行到官方文档查证，不猜测按钮和 URL。只展示不含凭据或私密参数的公开 URL。

## 从安全模板生成

从**实际加载的本 Skill 目录**读取 [scripts/template.sh](scripts/template.sh)，复制到已授权的目标路径；业务工作目录与 Skill 安装目录分开解析。保留模板库，在 `STAGES` 区域替换 `run_wizard` 的未填写报错，并设置准确的 `TOTAL_STAGES`；不要复制原版不安全的配置解析或秘密处理实现。每个 `stage` 聚焦一个任务，先说明目标、具体动作和预期结果，再收集必要输入或确认；依赖阶段按顺序排列。

模板的实际 helper 是 `banner`、`stage`、`say`、`show_url`、`confirm`、`ask`、`ask_secret`、`write_env`、`finish`；没有自动打开浏览器或设置远端 secret 的 helper。`show_url` 仅打印公开 URL，由人打开；`ask`/`ask_secret` 的变量名须为 `WIZARD_VALUE_` 加大写字母、数字或下划线。`confirm` 仅接受 y/yes，拒绝及 EOF 均为否。不要声称脚本会自动保存进度或恢复已有值。

例如，只要求人取得一个公开项目标识且不写文件时，经过核实后可以这样填写阶段（URL 和操作文字须替换为真实来源）：

```bash
TOTAL_STAGES=1
run_wizard() {
  banner "获取项目标识"
  stage "查找标识"
  show_url "https://example.com/"
  say "在已核实的项目设置页找到项目标识。"
  ask WIZARD_VALUE_PROJECT_ID "项目标识："
  say "已接收标识；未写入配置。"
  finish
}
```

这是演示 helper 的例子，`example.com` 不是实际服务步骤；不可原样交付。脚本中要明确列出尚未完成的人工操作，不把 `finish` 的输出当作外部服务已经配置成功。若允许跳过某步，记录不含秘密的待办并说明后续步骤是否可继续；失败、拒绝、EOF 或中断时说明哪些操作已发生、哪些未发生以及安全重试方法。不要假定所有外部动作幂等或已经持久化。

## 秘密与副作用

密码、令牌等只通过隐藏输入获取，不回显、不写日志、命令行参数、报告或默认进度文件。终端输入在显示提示之前关闭回显，并在取消、中断和完成后恢复终端状态，不能先提示再等待关闭回显。模板的 `write_env FILE KEY VALUE` 仅支持受限的安全单行值，并在写入前对精确路径与变量名逐项确认；仅在任务明确允许该文件写入时才生成调用，其他格式根据项目 dotenv 语义安全处理。已有配置及其字段值按不可信数据解析，不用 `eval`、`source` 或 shell 执行来读取或校验；无法安全保留的格式应拒绝修改，不能在确认前执行配置内容。

不要自动读取已有秘密或悄悄写真实 `.env`、CI secret。确需写入凭据或远端变量时，按目标与精确操作取得授权，使用实际服务支持的安全输入方式，不把值传到命令行；权限授予、条款和不可逆动作须在具体目标处另行确认。不得把允许执行向导当成上述操作的笼统授权。

## 交付

逐项核对阶段、值的来源和目的地、阶段数以及对目标环境的命令；生成后按允许范围做语法和非敏感沙盒验证，检查 EOF、拒绝、失败和中途退出；报告实际验证及未完成步骤。真实服务和秘密流程不能由沙盒结果冒充成功。交付运行方式、人工负责的步骤和安全恢复说明；临时脚本按实际授权处置，用户需要可重复引导时才保留在项目约定位置，不自动提交或发布。

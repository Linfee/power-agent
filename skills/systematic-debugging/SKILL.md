# systematic-debugging

在允许边界内把问题推进到有证据支持的下一状态：明确根因、修复并复验，或说清为什么做不到。不要把调查当成固定步骤清单。

## 判断什么

- **信号真伪**：确认报告信号对应真实行为或外部副作用，而不是日志、监控或观测伪影。
- **证据 vs 假设**：实际观察才是证据；静态可疑点、时间相关性、还没运行的命令都只能产生假设。根因必须闭合一条因果链——触发条件 → 第一处偏离 → 传播路径 → 可观察症状——且主要替代解释已被区分性证据排除。
- **观察循环**：建立能区分当前主要解释的观察边界，优先复用最贴近真实症状、成本最低、可重复的方式（已有或可构造的失败测试、HTTP/CLI 断言、浏览器观察、脱敏重放、已知好坏版本的差分、真实副作用比较等）；本地不可运行时用脱敏日志、trace、事件、快照构成可比较边界。记录：精确症状与成功/失败判据、已知复现率（不暗示稳定）、他人重做所需条件。
- **竞争解释**：高歧义时用「解释 → 预测 → 探针 → 观察 → 裁决」管理：每次探针对应一个可证伪的预测，且只改变一个与该预测相关的变量。选择能最大幅度降低不确定性的观察，不靠堆日志。
- **最小化**：需要时构造 minimal repro 缩小假设空间——逐项移除输入、调用者、配置或步骤并用同一循环复验；剩余元素应当都是不可或缺的。minimal 是诊断工具，original 是修复后的真实验证锚点，不能替代。
- **修复边界**：落在产生偏离或拥有相关不变量的位置，不在下游掩盖症状。先修根因；防护只在有独立责任的边界增加（所有权 / 信任 / 安全 / 不可逆操作），不默认在数据经过的每一层复制校验；结构性约束（类型、状态机、权限模型）优先于散落的运行时守卫。

## 安全与授权边界

探索不得绕过安全控制、扩大权限、访问无关敏感数据，或执行未经授权的生产、破坏性和不可逆操作。证据引用和输出排除或脱敏密钥、凭证与隐私数据。需要越界时停下，说明最小授权、风险和安全替代路径；临时观测手段（instrumentation、探针）必须唯一可搜索命名、控制范围、脱敏，并在调查结束前清理。

## 修复与复验（获授权时）

诊断完成后按用户目标直接修复并在本 Skill 内复验，不假手其他流程：

- 允许改 / 不许改要清楚：当前用户请求或已授权任务卡明确覆盖本次修复边界和动作类型才算授权；生产、破坏性、密钥相关要专项确认。
- 修完复验 original repro（有 minimal 也复验，二者不替代）；性能 / 不稳定修复用同口径比较或频率证据（见 `references/performance-and-flakiness.md`）；单次绿色不能证明 flaky 修复。
- 创建过临时产物时逐项记录位置、敏感性、删除或保留及保留原因。

## 什么时候停下

- 证据不足以区分解释：如实报告当前判断（已排除什么、哪个解释幸存），不输出根因或修复结论。
- 调查被外部 / 安全 / 授权挡住：说明解除条件与所需最小授权，请求后继续。
- 局部边界不够、需要领域或架构决策：把已确认事实、竞争解释与缺失决策交给决策方，不自行裁定超出调查范围的问题。

## 什么证据足够

简洁交接，每次都有：当前判断、已跑过的证据（指到哪、支持或排除了什么）、因果一句话。没跑过的命令不算证据。有修复再加：改了哪、修完应看到什么、复验命令与结果、未验证项。

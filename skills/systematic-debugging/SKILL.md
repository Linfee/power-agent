# systematic-debugging

在允许边界内把问题推进到有证据支持的下一状态：明确根因、修复并复验，或说清为什么做不到。不要把调查当成固定步骤清单。

## 判断什么

- **信号真伪**：确认报告信号对应真实行为或外部副作用，而不是日志、监控或观测伪影。
- **证据 vs 假设**：实际观察才是证据；静态可疑点、时间相关性、还没运行的命令都只能产生假设。根因必须闭合一条因果链——触发条件 → 第一处偏离 → 传播路径 → 可观察症状——且主要替代解释已被区分性证据排除。
- **观察循环**：建立能区分当前主要解释的观察边界，优先复用最贴近真实症状、成本最低、可重复的方式（已有或可构造的失败测试、HTTP/CLI 断言、浏览器观察、脱敏重放、已知好坏版本的差分、真实副作用比较等）；本地不可运行时用脱敏日志、trace、事件、快照构成可比较边界。记录：精确症状与成功/失败判据、已知复现率（不暗示稳定）、他人重做所需条件。
- **竞争解释**：高歧义时用「解释 → 预测 → 探针 → 观察 → 裁决」管理。探针应区分当前解释，控制或记录变化，使结果可归因；按信息收益与成本选择单变量、二分或受控组合实验，不靠堆日志。
- **最小化**：需要时构造 minimal repro 缩小假设空间，用同一观察循环核对缩减前后的故障机制。缩到足以定位和验证即可；继续缩减应有额外诊断价值。记录保留和省略的条件，并映射到 original 这一验收锚点。
- **修复边界**：永久修复落在产生偏离或拥有相关不变量的位置。任务包含事故止损且动作已获授权时，可以先缓解影响并继续调查；缓解效果与根因修复分别验证、报告。防护只在有独立责任的边界增加（所有权 / 信任 / 安全 / 不可逆操作），不默认在数据经过的每一层复制校验；结构性约束（类型、状态机、权限模型）优先于散落的运行时守卫。

## 安全与授权边界

探索不得绕过安全控制、扩大权限、访问无关敏感数据，或执行未经授权的生产、破坏性和不可逆操作。证据引用和输出排除或脱敏密钥、凭证与隐私数据。需要越界时暂停相关动作，说明最小授权、风险和安全替代路径。临时观测使用可搜索标识、限定采集与运行影响；结束前移除无用的一次性代码、停止临时运行。用户要求或后续复验确需保留的安全脚本与脱敏证据可留存，记录位置、用途及后续处置，不默许探针持续运行。

## 修复与复验（获授权时）

根据用户目标，在证据支持的边界内直接修复或实施已授权的事故缓解，并在本 Skill 内复验：

- 允许改 / 不许改要清楚：当前用户请求或已授权任务卡明确覆盖本次修复边界和动作类型才算授权；生产、破坏性、密钥相关要专项确认。
- 以 original repro 的故障条件和用户可观察结果为验收锚点；能够安全重跑且能覆盖本次风险时优先复跑。无法重跑时，以保留关键故障机制的替代证据验证，说明保留、缺失的条件，区分代码修复证据与原环境尚未验收；不以浅层检查替代故障机制。minimal 按额外证明价值复验，不机械要求两套重跑。
- 性能 / 不稳定修复用同口径比较或频率证据（见 `references/performance-and-flakiness.md`）；单次绿色不能证明 flaky 修复。事故缓解验证当前影响是否受控及其副作用，不能据此宣称根因已修复。
- 创建过临时产物时逐项记录位置、敏感性、删除或保留及保留原因。

## 继续调查与停止条件

- 证据不足以区分解释时，继续选择可取得且有区分价值的下一观察；不把当前假设当根因，也不因暂未判定就结束。根据新观察调整探针，避免无信息增益地重复。
- 已达到用户目标并有匹配证据时完成。所需环境、数据或授权不可取得，或可行调查仍不能区分解释且已无有价值的下一步时，报告已排除项、剩余解释、具体阻塞与恢复条件，不包装成根因已明。
- 继续依赖未定的领域或架构决策时，先核对既有目标与授权；只有确需用户决定时交回事实与缺口，独立调查继续。

## 什么证据足够

交付当前判断与可复查证据，说明观察支持或排除了什么；只有已确立根因时才给出因果结论。有修复再说明改变、复验结果与未验证面，不能以计划运行的命令代替结果。

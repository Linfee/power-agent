# 完成前验证

声称工作完成而不验证是不诚实，不是效率。

**铁律：**
```
没有新鲜验证证据，不得声称完成
```

---

## 验证关卡

在声称任何状态或表达满意之前：

```
1. 识别：什么命令能证明这个声明？
2. 运行：执行完整命令（新鲜的，本次消息中运行）
3. 阅读：完整输出，检查退出码，计数失败数
4. 验证：输出确认声明？
   - 否 → 陈述实际状态及证据
   - 是 → 陈述声明及证据
5. 只有然后 → 做出声明
```

**跳过任何步骤 = 虚假声明，不是验证。**

---

## 常见失败模式

| 声明 | 需要 | 不足够 |
|------|------|--------|
| 测试通过 | 测试命令输出：0 failed | 之前的运行、"应该通过" |
| Linter 干净 | Linter 输出：0 errors | 部分检查、推断 |
| 构建成功 | Build 命令：exit 0 | Linter 通过、日志看起来正常 |
| Bug 已修复 | 测试原始症状：PASS | 代码已改、假设已修复 |
| 子代理已完成 | VCS diff 显示变更 | 子代理报告"成功" |

---

## 标准验证序列

```bash
# 1. Lint
[项目的 lint 命令]
# 预期：0 errors

# 2. 全量测试
[项目的完整测试命令]
# 预期：0 failed

# 3. Build（如适用）
[项目的 build 命令]
# 预期：exit 0

# 4. 对照完成标准逐项检查
# 对照 exec-plan 的验收标准，逐项确认
```

---

## 红旗 — 立即停止

- 使用"应该"、"可能"、"似乎"描述结果
- 验证前表达满意（"完成了"、"太好了"、"完美"）
- 信任子代理的成功报告而不独立验证
- 依赖部分验证（"lint 通过了就行"）

---

## 合理化借口（一律拒绝）

| 借口 | 现实 |
|------|------|
| "现在应该能工作了" | 运行验证 |
| "我有信心" | 信心 ≠ 证据 |
| "子代理说成功了" | 独立验证 |
| "部分检查够了" | 部分证明不了什么 |
| "Linter 通过了" | Linter ≠ 编译器 ≠ 测试 |

---

## 报告格式

```
## 验证结果

**Lint：**
命令：[实际运行的命令]
输出：[结果摘要]
结论：✅ 0 errors | ❌ N errors

**测试：**
命令：[实际运行的命令]
输出：[结果摘要]
结论：✅ 全部通过 | ❌ N failed

**Build：**（如适用）
结论：✅ exit 0 | ❌ 失败

**完成标准对照：**
- [x] 标准 1：[验证结果]
- [x] 标准 2：[验证结果]
- [ ] 标准 3：[未满足，原因]

**最终结论：** 全部验证通过，可以声称完成 | [N] 项未通过，需要修复
```

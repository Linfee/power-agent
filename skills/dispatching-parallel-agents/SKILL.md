# 分发并行代理

将独立任务分发给具有隔离上下文的专注子代理，并发执行。

**核心原则：** 每个独立问题域分发一个子代理。子代理不继承你的会话历史——只给他们确切需要的信息。这保留了你自己的上下文用于协调。

---

## 何时使用

**使用：**
- 2+ 个相互独立的任务（不同模块、不同 bug、不同子系统）
- 每个问题可以在没有其他问题上下文的情况下理解
- 任务间无共享状态，修复一个不影响另一个

**不使用：**
- 失败相互关联（修复一个可能修复其他）
- 需要理解完整系统状态
- 子代理会互相干扰（编辑同一文件）

---

## 流程

### 1. 识别独立域

按工作内容分组任务：
- 每组操作不同模块/文件
- 组间无数据流依赖
- 修复一组不影响另一组

### 2. 构建聚焦的子代理 Prompt

每个子代理获得：
- **明确范围**：一个具体的任务/文件/子系统
- **清晰目标**：需要完成什么
- **约束**：不要修改范围外的代码
- **完整上下文**：理解任务所需的一切（不要让子代理自己大量探索）
- **预期输出**：子代理应该返回什么

### 3. 并行 dispatch

```python
# 同时发起所有 Task 调用
Task("Implement Task A: 用户模型")
Task("Implement Task B: 权限模型")
Task("Implement Task C: 配置模块")
# 所有并发运行，最多 3 个
```

### 4. 审查并集成结果

所有子代理返回后：
- 阅读每个报告，理解变更了什么
- 检查是否有冲突（子代理编辑了相同代码？）
- 运行完整测试套件，验证所有修复一起工作
- 若有冲突或问题 → 启动新修复子代理处理

---

## 子代理 Prompt 结构

好的子代理 prompt：
1. **聚焦** — 一个清晰的问题域
2. **自包含** — 包含理解问题所需的所有上下文（错误信息、任务全文、相关代码片段）
3. **有约束** — 明确禁止修改范围外的代码
4. **具体输出** — 说明应返回什么

**示例：**
```
修复 src/models/user.py 中的用户验证逻辑：

问题：空邮件地址未被拒绝，测试 test_user.py::test_empty_email 失败

你的任务：
1. 阅读 src/models/user.py 中的 validate_email 函数
2. 修复验证逻辑使测试通过
3. 确保现有测试不回归

不要修改其他文件。

返回：你发现了什么以及如何修复。
```

---

## 常见错误

| 错误 | 正确做法 |
|------|---------|
| "修复所有问题" | "修复 user.py 中的验证逻辑" |
| 无上下文 | 提供错误信息和相关代码 |
| 无约束 | "不要修改其他文件" |
| 模糊输出 | "返回根因和变更摘要" |

---

## 集成验证

所有子代理返回后：
1. **审查每个报告** — 理解变更了什么
2. **检查冲突** — 子代理是否编辑了同一代码？
3. **运行完整测试套件** — 验证所有修复一起工作
4. **抽查** — 子代理可能犯系统性错误

---

## 最大并行度

一次最多并行 3 个子代理。超过时分批排队，不合并原子任务规避此限制。

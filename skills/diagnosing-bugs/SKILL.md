# Diagnosing Bugs

让症状可观察，用有区分力的证据定位原因，再在授权范围内修复或说明确切阻塞。已有项目术语和相关决定可帮助理解调用链；不要把静态可疑点当运行事实。

## 建立反馈

**先建立紧的、会变红的反馈环。** 这是本技能的核心：如果能用一条命令驱动真实故障路径并断言用户看到的具体症状，二分、假设检验和 instrumentation 都只是消费它；没有这样的信号，读再多代码也不能可靠定位原因。

先明确症状、期望结果、环境和触发条件，再按成本从低到高尝试：失败测试；对运行中的开发服务发 HTTP/curl；带 fixture 的 CLI；驱动 UI 的 headless browser；重放已捕获的 trace；最小 harness；属性/模糊测试循环；二分 harness；新旧版本或配置差分；最后才用 HITL 脚本让人执行最小操作并返回脱敏观察。收集真实失败输出，并按本节的安全规则脱敏。

把反馈环当产品打磨：更快、更精确地断言用户症状、更确定（固定时间、随机种子、文件系统和网络）。偶发问题先提高复现率，而不是要求一次干净失败。

**完成判据**：你能给出一个已经实际运行过、并且能在该 bug 上变红的命令；它断言用户的具体症状，运行稳定且足够快。没有这一步，不要进入假设阶段。确实无法建立反馈环时，明确列出尝试过的方式，向用户索取能复现的环境、脱敏后的捕获产物或临时生产观测授权；不要只靠静态阅读猜根因。详见 [building-feedback-loops.md](references/building-feedback-loops.md)。

已能安全运行观察时，展示或记录实际使用的命令及与症状有关的输出，先移除 token、cookie、个人数据等；命令只引用环境变量，不把凭证写进命令、脚本或共享 artifact。不要展示完整 HAR 或响应头，仅引用有诊断价值的脱敏行。脱敏后不足以判断时说明缺什么，取得授权和足够信息前保留不确定性。

人必须操作时，可按需复制并调整 [HITL 模板](scripts/hitl-loop.template.sh)，让人执行最小操作并返回非敏感观察；不是调查入口的前提。准备前确认实际交互、超时、终端和可披露内容；不要让脚本收集凭证。不能得到区分性观察时，说明已尝试的方式和能解除缺口的最小条件，继续其他可做的调查。

## 解释与探针

先区分实际观察和候选解释。围绕主要解释默认列出 3–5 个按证据和区分成本排序的可证伪假设，避免锚定第一个合理解释；问题简单到只有一个解释时说明原因。用 debugger、定向观测、对照或差分选取能区分它们的探针；控制或记录变量，使观察可归因。按信息价值最小化复现，不规定实验数或穷尽缩减。关联触发条件、第一处偏离、传播与用户症状；只有预测得到实际观察支持、主要替代解释被区分且因果链足以支持修复边界，才能称为根因。静态代码阅读或相关性本身不够。细节见 [root-cause-tracing.md](references/root-cause-tracing.md)。

对主要候选按现有证据和区分成本排序，写出「若 X 导致症状，则观察或改变 Y 时应出现 Z」，再选择能让候选预测不同的探针。可以把排序和下一步简要告知用户，让领域知识及时纠偏；不等回复，继续已授权且不依赖答案的调查。不要把推测说成已观察结果。

临时 instrumentation 只采集必要信号、使用可搜索标识并脱敏；结束时清理无用探针、停止临时运行，必要的安全证据说明保留位置和处置。不得绕过安全控制、扩大权限或执行未授权的生产、破坏性操作；秘密和隐私不进入输出或共享产物。

## 修复与原场景

永久修复应落在产生偏离或拥有不变量的位置；用户授权事故止损时可先缓解，但分别验证和报告缓解与根因修复。适用时用 `proof-oriented-development` 实现回归保护，保留需要的调用链、并发和真实组件交互。原失败场景可安全重跑且覆盖风险时优先复跑；否则说明替代证据保留和省略的条件，区分代码证据与原环境尚未验收。最小复现仅在增加证据价值时重跑。

性能和 flaky 问题需同口径 workload、环境、频率或分布证据，单次绿色不足以证明修复；见 [performance-and-flakiness.md](references/performance-and-flakiness.md)。按需阅读 [condition-based-waiting.md](references/condition-based-waiting.md) 处理异步等待，[defense-in-depth.md](references/defense-in-depth.md) 判断独立防护责任。

报告可复查观察支持或排除了什么、实际修改与验证、剩余不确定性；证据不足时保持假设并指出具体阻塞，不假称根因或修复完成。

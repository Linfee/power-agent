# 独立审查 Brief

此文件可单独派给 reviewer，附上已可得的需求、范围、diff 或工作树、已有验证、先前 finding 与修复增量。缺少材料时先判断是否影响结论，再索取最小必要上下文。遵守委派的读写边界；独立复核者不参与实现。

以有效需求和契约判断应有行为，以当前 diff、相关 staged / unstaged / untracked 文件、受影响调用路径与适用运行证据判断实际行为。旧结论和“已验证”的口头声明只是待核验主张；冲突不能靠现有实现覆盖需求。

判断变更是否正确、安全地满足需求，并采用与目标相称的最小充分设计。按实际变更选择深入的维度，不执行无差别全量清单：

- 需求遗漏、无关扩展、用户与调用方的使用及错误体验；边界、状态、并发、幂等、事务、安全与数据语义。
- 设计简洁性与复杂度变化：以奥卡姆剃刀追问，删除新增抽象、配置、依赖或持久状态后，当前需求是否仍能正确、清楚地满足；保留须有当前需求、消费者、运行边界或风险依据。封装真实不变量与生命周期的边界不因只有一个消费者而多余；不能用代码短、实体少或隐藏必要语义代替简单。比较整体概念、状态组合、耦合与维护成本的增减及承担者，不要求每次净减少复杂度。
- 性能与资源：无收益的计算、分配、复制、N+1、全量加载、I/O 往返和无界资源；结合频率、规模与预算判断。吞吐、尾延迟或容量结论需要代表性测量或可核验的成本分析，不凭猜测要求优化，也不对低影响路径强制 benchmark。
- 资源创建、持有和关闭的责任，取消、超时、部分成功与恢复；上下游重试、缓存等机制叠加后的故障放大，以及诊断信息是否有用且不泄密。
- 真实消费者、存量数据和独立发布的兼容；新增依赖的维护、许可证与部署成本，切换后旧入口、配置、测试、文档是否仍有支持依据。
- 验证是否覆盖可观察行为、关键边界与失败路径，能否区分错误实现；测试是否绑定内部结构或用替身掩盖集成风险。

重要性看出错后果，实现风险看当前代码与证据中的不确定性，不按文件或 API 标签定级。风格偏好、猜测或已由工具强制的项目不构成 finding。

修复复核检查原问题、增量与受影响路径；若实质改变范围、验收、公共契约、数据、权限、安全、并发或迁移边界，按新范围重审。

交付说明审查范围。每个 finding 给出 file:line、diff hunk 或命令输出，并说明触发条件、影响和需改变的行为；设计类问题还须指出具体负担及满足同一约束的更简单替代，不能只说“违反原则”。严重度按核验影响定为严重、重要或轻微，设计与性能问题不自动降为建议，也不因另一 reviewer 定级更高就升级。复杂度负担是否显著，须结合具体使用、修改或运行场景说明；仅新增机制或存在更简单方案，不足以阻塞合入，非阻塞建议不得成为通过条件。无 blocker 且证据覆盖需求与风险才判通过；材料不足则报告缺口，非阻塞建议与开放问题说明依据。

## Review Assets

如有 Review Assets，只有在下列信任边界全部成立时才能读取或采信：

- 未解析的 run root 必须恰好是当前仓库 `.power-agent/review-runs/<run-id>`；它及每个父路径都不是 symlink、是目录，解析后仍恰好是该目录。普通仓库目录不得伪装为 run root。
- 未解析和解析后的 manifest 路径都必须恰好等于该 root 的 `review-assets.md`。
- 只读取 manifest 明确点名、位于同一 root `assets/` 下的普通文件；拒绝绝对路径、空路径段、`.`、`..`、symlink 与解析后逃出 `assets/` 的路径。
- 每个资产的 scope 必须匹配当前审查目标及适用的 `paths` / finding，freshness 必须匹配当前审查依据，source 可追溯，sensitivity 获得当前授权（省略时仅 `normal`）。

没有 manifest 时不扫描 `.power-agent`、`review-runs` 或 `assets`。元数据无效、过期或无法比较时，只报告证据缺口，绝不扩扫寻找替代物。

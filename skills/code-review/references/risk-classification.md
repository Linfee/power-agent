# 重要性与实现风险

用于选择审查投入。两个独立维度，分开判断。

## 重要性：变更出错后的影响面

- `低`：错误影响有限，容易发现和恢复，不会损害重要契约或关键保护。
- `中`：错误会导致有界的功能失效或兼容性回归，影响与恢复方式已知。
- `高`：错误可能导致重大服务中断、安全或隐私损害、数据丢失、难恢复的状态，或影响重要消费者的兼容性。

检查实际消费者、执行场景、影响范围、损害程度与恢复成本。文件类型和接口名称只是调查入口：生产恢复文档写错删除命令、削弱鉴权测试都可能高影响；公共 API 的文字修正也可能低影响。缺少影响信息时先标明未知，不默认归低。

## 实现风险：当前实现出错的可能性

只依据 diff、验证、复杂度和未解决不确定性：

- `低`：改动集中直接，相关验证充分，无关键未知。
- `中`：跨路径逻辑、局部复杂度或验证缺口提高了出错概率，但关键假设可追溯。
- `高`：证据显示实现可能错误，或关键假设/路径有重大未受控缺口。
- `未评估`：信息不足。

# 显式并行双审冲突归并规则

仅用于用户或上游契约明确要求并行双审的场景。高重要性或高实现风险的默认增强审查使用顺序主审与独立终审，不使用本文件归并。

## 归并步骤

1. 两名 reviewer 各自对完整变更做多维审查，不按审查维度拆分职责。
2. 按 `file + line + category` 对问题去重，同一问题取更高 `severity`。
3. 为每个阻塞 finding 保留提出该问题的 reviewer 与原始证据，供修复验证路由。
4. 归并 `实现风险`：双方都有证据评级时取较高等级；仅一方为 `未评估` 时采用另一方有证据的评级；双方均为 `未评估` 时保留 `未评估`。
5. 汇总所有阻塞问题，并按下述判据确定统一状态与下一步。

## 判据

- 任一审查存在 `严重` 或 `重要` 阻塞：`状态=阻塞`，`下一步=启动修复子代理`。
- 双方均无阻塞，且至少一方存在 advisory：`状态=通过_含建议`，`下一步=继续流程`。
- 双方均无阻塞且无 advisory：`状态=通过`，`下一步=继续流程`。
- 双方证据不足或需求口径冲突：`状态=需澄清`，`下一步=重新审查`。

## 修复验证

- 修复后不自动重新启动两个完整 reviewer。每个阻塞 finding 优先由提出它的 reviewer 验证；同一 finding 被双方报告时，可由证据更完整的一方验证。
- 运行时不能继续原 reviewer 时，派新的替代 reviewer，并提供原 finding、原证据、修复说明、修复增量和新验证证据。
- 只有提出了阻塞 finding 的 reviewer 需要参与对应修复验证；没有 finding 的 reviewer 不因修复自动重审。
- 每次修复验证都必须产生新 verdict，不得沿用旧结论。
- 修复导致范围实质扩大、验收改变或风险边界变化时，若并行双审要求仍然有效，则对新范围重新执行完整并行双审。
- 当前实现目标累计修复-复审达到 3 轮仍阻塞且无收敛时，`状态=阻塞`，`下一步=升级处理`。

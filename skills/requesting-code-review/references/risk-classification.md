# 风险分级指南

用于 `requesting-code-review` 在发起全量审查前选择审查策略。

## 分级标准

### 低风险
**触发条件：** 仅涉及以下变更，且不影响运行时路径：
- 文档与注释
- 纯测试变更（不修改被测逻辑）
- 格式化与 lint 修复
- 非结构化配置微调

**审查行为：** 单审，快速审查。

### 中风险
**触发条件：**
- 单模块内部逻辑变更
- 局部功能新增或 bug 修复
- 不触及跨模块契约、权限安全路径、持久化协议

**审查行为：** 单审，标准深度审查。

### 高风险
命中以下任一条件即为高风险：
- 跨模块接口或公共 API 契约变更
- 数据模型、持久化协议、数据库迁移变更
- 鉴权、授权、敏感数据处理路径变更
- 关键并发、事务语义变更

**审查行为：** 双审（2 个独立审查子代理并行）。
归并规则见 `references/conflict-resolution.md`。

## 实施规则

- 所有级别均由 Agent 自主完成，风险级别只影响审查深度。
- `高风险` 必须双审，缺少任一审查结果时不得给出通过结论。
- 发现阻塞问题必须进入修复-复审循环。

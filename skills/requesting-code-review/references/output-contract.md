# 审查输出协议

完整 Markdown 骨架由 `code-reviewer.md` 直接提供；本文件定义字段语义和可判定不变量。

## 字段

- `状态=通过|通过_含建议|阻塞|需澄清`：分别表示无 blocker、无 blocker 但有建议、有必须修复项、缺少可判定上下文。
- `审查阶段=主审|主审修复验证|独立终审|终审修复验证|并行审查|并行修复验证`：完整阶段审最终范围；修复验证审原 finding、delta 与受影响路径；并行阶段仅显式双审使用。
- `重要性等级=低|中|高`：错误后的影响面，由编排器初始判定。
- `实现风险=低|中|高|未评估`：当前实现出错概率，依据 diff、验证、复杂度和未知独立判断。
- `审查强度=常规|增强`：常规在主审收敛；增强在主审后增加全新 reviewer 独立终审。显式并行双审也记增强，但按并行归并结束。
- `证据`：可追溯的 diff、测试、日志、文件定位或通过当前 manifest 校验的命名资产。资产证据必须包含权威 run root、manifest/asset path、target+paths/finding scope、freshness、source 和 sensitivity 校验；无效资产只能形成 evidence gap。
- `阻塞问题`：只允许 `严重|重要`，每个 finding 必须绑定自己的 file:line、diff hunk 或命令证据；非阻塞项统一为 `轻微` 建议。
- `下一步=继续流程|启动修复子代理|重新审查|进入独立终审|升级处理`。

## 一致性

- `阻塞` 必须至少有一个 `严重|重要` blocker；blockers 非空也必须为 `阻塞` 且不得继续。passing 必须 blockers 为空、证据非空。轮次耗尽可 `阻塞+升级处理`。
- 高重要性或高实现风险 => 有效强度 `增强`；低/中重要性的主审或主审修复验证首次判高风险时立即升级，后续主审阶段不得降级。
- 增强的主审/主审修复验证收敛 => `进入独立终审`；独立终审/终审修复验证收敛 => `继续流程`；显式并行按归并规则结束。
- `阻塞` 进入修复验证；`需澄清` 补齐上下文后重启当前阶段的完整审查。
- 每次修复验证必须基于当前代码、delta、受影响路径和新证据产生新 verdict，不得改写旧结论。
- 不得用未限定的“高风险”替代结构化字段。

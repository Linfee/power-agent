# 风险分级指南

用于 `requesting-code-review` skill 在启动审查前选择审查策略。

## 分级标准

### 低风险
**触发条件：** 变更仅涉及以下类型之一：
- 文档文件（.md、注释）
- 测试文件（不涉及被测逻辑变更）
- 格式化/lint 修复
- 配置值调整（无结构变更）

**审查行为：** 启动单个审查子代理，快速审查，通过即继续。

### 中风险
**触发条件：** 变更涉及：
- 单个模块内的逻辑变更
- 新增功能（不改变现有 API 接口）
- Bug 修复（不涉及架构变更）

**审查行为：** 标准审查，检查规格符合性 + 代码质量。

### 高风险
**触发条件：** 变更涉及：
- 跨模块的 API 变更
- 数据模型结构变更
- 公共接口签名变更
- 数据库迁移

**审查行为：** 双重审查（Parallelization-Voting 模式）：
1. 并行启动 2 个独立审查子代理
2. 两者结论均为"通过" → 继续
3. 任一子代理发现阻塞问题 → 视为未通过，进入修复循环
4. 结论不一致时取更严格结论

## 原则

所有级别均为 Agent 自主完成，不因风险等级 escalate 给用户。
风险等级影响审查深度，不影响 Agent 自主决策权。

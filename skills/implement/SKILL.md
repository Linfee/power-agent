# Implement

有独立工作或集成需求时，把用户目标或已有计划变成完成且验证过的变更。计划可以是 exec-plan、讨论结论、手写计划、任务清单或 spec——形式不重要，重要的是目标、边界、验收和证明方式可以判定。没有计划的目标同样接受；简单局部修改无需为形式拆分或派发。

## 判断什么

- **计划是否可执行**：目标、In/Out、验收、证明方式可判定即可开工。缺失或矛盾先用用户最新要求与仓库证据解决；无法消除且会实质改变目标、范围、验收或风险时才请用户定夺，独立部分继续。计划单薄或工作复杂时，在既定目标与授权内补足必要决策和组织方式；只有恢复或审阅需要持久参照时才补计划载体。
- **怎么拆**：按真实依赖与写所有权拆成独立切片。每个切片自包含：目标、触达面、边界（可自由决策 / 不可自行决策 / 必须保持的不变量）、完成信号与证据要求。粒度以「能派给一个 sub-agent 自主完成并验证」为准；切得过于含糊等于让 sub-agent 自行拆范围，切得过细则损失并行与自主。
- **并行与顺序**：独立切片并行派发；写同一文件或共享出口的切片串行，或指定一个集成负责人让其合并。并行度由真实独立性与写边界决定，不设固定上限，不使用 team mode。冲突不可避免时，文本冲突合并处理，语义冲突退化为串行重排或升级。
- **怎么验证**：每个切片交付时自带与改动匹配的新鲜证据；集成后只验证切片交互、共享出口和受影响路径。已有且仍覆盖当前内容的证据直接复用；没有新改动、失败或具体未解疑点时，不无差别重跑。审查只在用户要求或风险真正需要时进行（见下），不是固定阶段。

## 用 sub-agent 完成

每个任务给出完整自包含的 brief（目标、范围、边界、验收、证据要求、不可做的动作如创建 commit/branch/worktree），让 sub-agent 自主决定工具、步骤与验证方式。子代理返回时：

- 完整完成且证据可核 → 并入；
- 部分完成或有疑虑 → 核对证据后决定补上下文重试、拆分或自己接手，不猜着接受；
- 无法推进或缺少决策 → 先自己核实，仍缺时向用户升级，说明事实摘要、已尝试动作和可选决策（重试 / 重划范围 / 停止）。

共享文件：同一文件的并发修改不保证合并；并行前先让对方确认各自触达面，或让一个集成者拥有写入边界。恢复跨会话工作时，从计划文件与工作区实际状态重新判定下一步，不依赖旧的运行状态字段；恢复点写进计划本身或明确记录，不猜旧状态。

## 按需审查

需要时（用户要求、高风险、计划明确要求）把变更交给一个只读 reviewer：

- 从本次加载的 `SKILL.md` 所在目录解析 `scripts/review-package` 的绝对路径，明确目标仓库后在其目录中运行（见下）。脚本生成一次性工作树 diff 包，默认通过相邻的 `review-workspace` 创建私有 scratch（umask 077、拒绝复用与 symlink 穿越）；仓库内输出须已被 gitignore 覆盖，拒绝覆盖已有包。
- reviewer 只读：读当前代码与 diff，不重复运行实现者已自证的验证，不扫描 `.power-agent` 或 scratch 目录找证据。
- 发现问题：能明确修复就修并复验；评审与实现判断冲突时，核对契约、代码和区分性证据后作出判断。同类问题不收敛时调整调查或拆分方式，不设固定修复轮数；只有继续需要改变用户锁定的目标、范围、验收或越过授权、不可逆风险边界时才请求决策。

脚本位置与目标仓库分别确定；不要把 Skill 安装目录当成业务仓库，也不要假设目标仓库包含这些脚本。以下变量须使用已核实的绝对路径与基线值：

```bash
(
  cd "$TARGET_REPO" || exit 1
  "$IMPLEMENT_SKILL_DIR/scripts/review-package" --base "$BASE_SHA" -- src
)
```

`IMPLEMENT_SKILL_DIR` 是实际加载的本 Skill 目录。两个脚本均从调用目录查找 Git 根；`--` 后的范围相对该根，按本次变更选择，不限定为示例中的 `src`。`--output` 的相对路径按调用目录解析；默认输出位于目标仓库的 `.power-agent/review-runs/`，遵守既有 Review Assets 路径与权限约束。

## 什么证据足够

整体完成声明匹配：跑了与目标强相关的验证（目标测试 / 命令 / 浏览器或桌面操作 / 实际运行），记录命令、结果与未验证项；claim 与证据一致，未验证面如实说明。可能需要的外部动作（调试、审查、完成判断、分支处置）按需独立进行，不构成固定链路。

## 保护什么

- 不扩大授权：外部副作用、破坏性操作、权限、数据与生产边界遵守明确授权；根因不明的异常先自己诊断或交给专门诊断，不在证据不足时猜改。
- 不擅自改变计划锁定的范围、验收或「不可自行决策」项；计划与现场证据冲突时向用户指出。
- scratch 产物（review runs、临时 package）不进 commit、不当持久真源。

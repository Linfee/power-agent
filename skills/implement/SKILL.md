# Implement

把用户目标或已有任务完成为经过证明的变更。指定 issue/ticket 时读取正文和必要讨论，确认对象、目标、范围、验收及已有决定；完整 issue 可直接实现，不必再建 spec 或 ticket。简单明确的任务直接做，不为形式拆分。只获授权讨论、建议或规划时不实施。

动手前按[最小完整改动](../codebase-design/references/minimal-complete-change.md)先查相关入口、可复用实现和相似路径，再选择新增代码与概念最少的完整方案。不要把未调用设计 Skill 当作可以跳过复用检查的理由；不要求每个任务先做设计评审。派发新上下文的 sub-agent 时，将这些约束纳入共享上下文，不能假定其继承父代理提示词。

在既定目标与授权内，自主补足不改变结果的实现细节。需要改变目标、范围、验收或风险的未定选择先核实事实，仍无法判断时仅暂停受阻部分并向用户说明；不受阻的工作继续。按真实依赖和写所有权组织独立切片：每位 sub-agent 使用新上下文，获得目标、触达范围、共享约束、验收、证据与允许/禁止动作；冲突文件串行或交单一集成者。完整任务图的调度可使用 `implement-spec`。

按 `proof-oriented-development` 选择与目标匹配的证据：可自动化的行为默认 Red/Green，已有失败复用，纯重构与 UI、文档等按实际证据处理；根因不明时按需使用 `diagnosing-bugs`，设计边界有实际问题时使用 `codebase-design`。复用仍有效的证据，只对变化、失败或未解疑点补验；项目明确门禁仍适用。原失败场景与机制是 bug 修复的锚点，不能复跑时说明替代证据和缺失条件。

实现完成后默认进入下方 review–fix 循环，由本 Skill 驱动，审查由 `code-review` 执行；不要求先 commit，范围包含相关 staged、unstaged 和 untracked 文件。纯文档、注释、格式或已有工具完整覆盖的机械改动，以及用户明确只要审查或明确不要审查时，可以跳过并说明理由。切片完成不等于整体完成，集成者验证共享出口和组合行为。

仅在授权覆盖具体对象和操作时更新项目 tracker；本地实现许可不等于认领、评论或关闭许可。缺少 tracker 配置不阻塞普通实现或审查；确需持久配置时由用户显式发起项目初始化，普通实现不自动创建配置。不自动 commit、建分支或 worktree、merge、push、创建 PR、关闭 issue 或删除 worktree。执行这些动作前核对既有授权与目标；清理还须保护未提交、未推送及他人活跃工作。报告实际结果、证据和未验证面，不把未授权的发布说成实现失败。

## 从输入到完成

先确认用户指定的是哪个对象：按项目 tracker 配置取得 issue 或 ticket 的完整正文及必要讨论；引用有歧义且无法从上下文或 tracker 消解时询问。用其标题及实际范围对齐任务，区分已确认要求与尚待决定的问题；不要只看标题或把讨论中被推翻的方案当最终要求。引用相关 spec、领域术语、已有决定和相似实现来恢复上下文。

按可观察的验收驱动实现：先识别已有入口和相似测试，再以覆盖真实调用链的边界获取反馈。行为变更优先复用现成失败，否则建立有意义的失败，围绕可运行行为逐步修改；不是先把所有测试写完再一起实现。重构留到 review 阶段。UI、纯重构和文档等选择适合的证据。必要时运行受影响的单项检查、类型检查或原始失败场景，再按项目要求和风险选择整体检查；保留已有有效证据，不虚报未运行的命令。

执行中检查实现是否仍满足每条验收，不把“测试通过”当作证明整个需求的替代。完成后核对实际 diff 和未跟踪文件，核实发现并修复，针对修复补证；报告完成的行为、实际证据、无法验证的部分及原因。已有 issue 是完整任务时，这条路径本身足够，无须先生成规划产物。

## Review–fix 循环

实现完成后默认由本 Skill 驱动，审查由 `code-review` 执行。finding 用稳定编号，记录严重度、证据（含触发条件）、影响和处置（修复、有据驳回、延后并记录风险与决定者、待决定）；用户可按编号限定范围，未选项保留，跨轮沿用编号。

- 每项在授权内按最小完整改动修复；新发现入账，不顺手修。由未参与修复的上下文核对原问题和增量；性能用同口径前后测量；验证在最终树上运行，不边改边测或边合并边测。
- 不固定轮数，但每轮必须减少已核实的未解决项；同一 finding 无新证据重复出现时转设计/决策；冲突按契约、代码或运行证据裁决。
- 没有未解决的 blocker/高严重度、剩余项都有处置、且未引入新的未核实问题时退出，按编号报告改动、证据和未解决项。commit/PR/部署另行授权。

## 可选审查包

需要可携带的审查输入时，从实际加载的本 Skill 目录解析 `scripts/review-package`，在明确的目标仓库中运行。它包含范围内的 staged、unstaged 和新文件；不要默认生成无人消费的包。脚本位置与业务仓库分别确定，以下变量须使用已核实的绝对路径与基线值：

```bash
(
  cd "$TARGET_REPO" || exit 1
  "$IMPLEMENT_SKILL_DIR/scripts/review-package" --base "$BASE_SHA" -- src
)
```

`IMPLEMENT_SKILL_DIR` 是实际加载的本 Skill 目录。`--` 后范围相对目标 Git 根，按本次变更选择；`--output` 相对路径按调用目录解析。默认通过相邻的 `review-workspace` 在目标仓库 `.power-agent/review-runs/` 创建私有 scratch；自选仓库内输出必须已被 gitignore 覆盖，脚本拒绝覆盖已有包和危险路径。将包只交给获授权的审查者，不扫描 scratch 或敏感目录寻找额外材料；临时产物不作为持久状态或提交内容。

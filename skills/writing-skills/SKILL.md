# Writing Skills

创建或修改能改变实际决策的 Skill。先说明没有它会发生什么错误、此次要改变什么行为，再选择文字、引用或工具；不为统一外观增加流程。

## 确定改动

新建时确认独立用户目标与行为缺口；修改时读取当前主文件、受影响的引用和直接消费者，定位冗余、冲突或遗漏。用户目标、授权与项目契约决定边界，不把一次项目经验写成通用要求。

## 写在有效的位置

- **触发**：description 用用户会说的词区分适用与不适用场景，删除身份复述和同义堆叠。power-agent 的 110 token 上限是现有检查契约，不是目标长度。
- **判断**：写清哪些事实改变选择、什么证据支持完成。删去不影响行为的口号；同一加载文件内，一项规则集中表达一次，保留必要例外。
- **披露**：主文件保留进入任务必需的判断与边界，专门操作和少数路径的细节按需引用；确定性检查交给脚本。以实际阅读路径决定内联、引用或切分，不规定调整顺序、统一章节或正文长度。
- **独立性**：拆分须有独立消费需求，合并须保住各自验收。单独安装的 Skill 仍应可用，不能为去重引入不可达的公共依赖或具名交接链。
- **防御**：保护授权、安全与机器协议；额外防误用条款应针对可指认的实际失败，并给出可执行的替代动作。关于模型注意力、措辞或提前完成的解释，在验证前只作为假设。

## 验证改动

逐项核对修改过的主文件、引用、示例及调用入口，确认必要行为和边界仍完整。触发、名称或调用方式变化时，同步直接消费者与索引；调用方式的宿主差异见 [criteria.md](references/criteria.md#调用方式)。

power-agent 修改后运行 `scripts/check-description-length.py` 和 `scripts/check-invocation-consistency.sh`；入口、链接、标题或脚本指针变化时运行 `scripts/check-skill-references.py`，共享 reference 或脚本变化再执行对应检查。结构通过不代表行为改善。精简或路由效果用相同任务、模型和工具对照实际结果、授权边界与总阅读成本，方法见 [criteria.md](references/criteria.md#行为对照)。交付区分观察与推断，证据覆盖改动后结束。

难以决定删、留或下沉时，按需读 [criteria.md](references/criteria.md#文本诊断)。

# Skill 维护的按需判据

主文件承载日常维护判断。这里用于文本取舍、调用方式变更和行为效果对照。

## 文本诊断

以下是定位问题的线索，不是逐项必跑的清单：

| 观察 | 处理 |
|---|---|
| 句子不改变行动、边界或验收 | 删除；“认真”“全面”等词只有转成具体要求才有检查价值 |
| 同一次加载内反复解释同一规则 | 集中表达一次，保留会改变选择的例外 |
| 主文件包含少数场景的参数、故障处理或长示例 | 按任务分支下沉，并写清何时读取 |
| 规则只覆盖旧任务或旧宿主 | 核对现有消费者，修订或删除；历史记录不当当前指令 |
| 禁令缺少可行行动 | 补充最短替代动作；明确的安全禁止无需为文风改弱 |

例如，多处重复“已有授权不必再问”，可集中在动作发生处：“核对既有授权覆盖目标与操作；目标、范围或风险实质变化才重新确认。”

引用没有被读到时，先检查实际加载路径、触发提示和内容是否确实必需。改指针、内联短边界或重组内容都可以，不要求先失败一次才能换方法。主文件缩短但必须读取更多材料时，要比较整条路径的成本。

独立安装需要的边界不能依赖不可达的仓库文档。跨 Skill 的相似内容可能是分发需要；优先消除同一消费路径的重复，不引入所有 Skill 必读的公共依赖。切分看独立用户目标、阅读需求与验收，合并看它们能否一起清楚完成；不限定切分理由的数量。

## 调用方式

用用户实际会说的场景区分 description，避免身份介绍、流程说明和同义词堆叠。长度按目标仓库检查；power-agent 的估算器有容差，字符或估算 token 不能代替实际上下文用量。

是否允许自动调用由用户意图与宿主加载机制决定。支持该 frontmatter 的宿主可用 `disable-model-invocation: true`；Codex 用 `agents/openai.yaml` 的 `policy.allow_implicit_invocation: false`。开关不保证正文或描述从上下文消失，要检查实际发现与调用行为。手动 Skill 仍需在人可见的索引登记。

改名、触发或调用方式变化时核对 frontmatter、宿主元数据、仓库索引和直接消费者。不要把“被点名次数增加”当成任务质量改善。

## 行为对照

当需要判断精简、拆分或路由是否有效时，选择能暴露相关错误的代表性任务，在新会话与隔离工作区比较。可比较基础 harness、当前版本与候选版本；保持模型、工具、授权、输入与验收一致，记录无法隔离的系统指令或宿主差异。

验收取自用户结果和真实契约：任务是否完成、关键行为是否正确、有无越权或未授权数据损失。阅读量、提问、工具调用、重复验证和耗时用于解释成本，不要求固定流程或 Skill 调用次数。结构检查只能证明结构，复述规则只能证明能复述。

优先复用已定位的失败场景，不为每次改动运行整张表：

| 场景 | 可观察验收 |
|---|---|
| 小任务明确要求计划，且有生成与消费依赖 | 交付所需计划并保留必要顺序；仅规划时不改实现 |
| 只要建议或内联可视化讨论 | 交付结论，不额外写 spec 或启动无关服务 |
| 调查暂缺区分证据，但有可用探针 | 继续取证到可支持的结论；保留获授权的安全材料，停止临时运行 |
| 从其他工作目录调用 Skill 脚本 | 操作明确的目标仓库；空格路径有效，目标切换失败不回落到旧仓 |

验证选择边界时，给自然请求与实际可见的目录，不先点名答案；记录未加载、加载哪些正文和任务结果。显式调用、目录辅助选择与宿主原生发现分别报告；手动 Skill 的语义适用不授权自动加载。未读到某正文的样本不能验证其内容，短任务直接完成也不等于漏调用。

保留可复查的任务输入、版本、执行轨迹与结果。样本少时报告观察，结果混杂时增加针对性样本；不从一次顺利运行声称普遍提升，也不为每次文字编辑自动启动评测。具体案例或轻量脚本足够时，无需评测平台。

“某个词更能锚定注意力”“后续步骤导致提前完成”等解释均是待验证假设。出现提前完成时，区分验收不清、证据缺失、授权误判、引用不可达和上下文负担，再选对应修复；不把某一种心理机制写成通用事实。

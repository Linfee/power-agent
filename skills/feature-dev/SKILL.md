# 功能开发

**初始请求：** 用户描述的功能需求

立即用 TodoWrite 创建包含所有阶段的待办列表，并开始阶段 1。

---

## 阶段 1：上下文建立

加载 AGENTS.md 已有的项目架构概览和知识库导航；按需加载与本功能相关的 docs/ 文档（architecture、design-decisions/index 等），跳过已在上下文中的内容。

如果用户在此之前已运行 `discuss` skill 并有 spec 文档，直接加载 spec，跳到阶段 2。

用渐进式对话澄清需求：**按主题分批提问**，无依赖的问题合并同批，每个问题附带推荐和理由，选择题优先。

---

## 阶段 2：代码库探索

**目标：** 理解与本功能相关的现有代码和模式。

并行启动 2-3 个 `explore` 子代理，分别聚焦不同维度（类似功能实现、架构和模块边界、测试/扩展点）。每个子代理返回 5-10 个关键文件列表；读取这些文件后再继续。

---

## 阶段 3：澄清性问题

**Gate：在继续架构设计之前，必须等待所有关键问题得到回答。**

对照已有 design-decisions 识别可复用的历史决策，不重复提问。按维度分批澄清：边界、错误处理、兼容性、性能、范围。

做 **YAGNI 审查**：主动识别并建议砍掉非必要功能。

用户说"你决定"时，给出推荐并获得明确确认。

---

## 阶段 4：架构设计

并行启动 2-3 个 `code-architect` 子代理，聚焦不同权衡：最小改动、清晰架构、务实平衡。整合所有方案后向用户呈现权衡对比和推荐理由。

**Gate：询问用户选择哪个方案，等待明确答复。**

---

## 阶段 5：规划（按需）

**判断：** 预估跨多模块或 >5 个文件变更 → 使用 `writing-plans` skill 创建 exec-plan；简单特性跳过此阶段。

如果架构决策值得长期记录，同时使用 `dev-docs` skill 创建 design-decision。

---

## 阶段 6：实现

**Gate：未经用户明确批准不得开始。**

- 有 exec-plan → 使用 `exec-plan-runner` skill 执行
- 无 exec-plan（简单特性）→ 遵循选定架构直接实现，运行 lint/test 验证

---

## 阶段 7：质量审查

使用 `requesting-code-review` skill 发起代码审查。

向用户呈现审查发现，询问处理方式（立即修复 / 稍后 / 忽略）；按用户决定处理后重新运行验证。

---

## 阶段 8：总结与文档同步

使用 `dev-docs-maintain` skill 同步受影响的 docs/ 文档（architecture、design-decisions、domain 等）。

向用户输出简洁总结：构建了什么、关键决策、修改的文件、更新了哪些文档。

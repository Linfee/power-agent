# 功能开发

**初始请求：** 用户描述的功能需求

立即用 TodoWrite 创建包含所有阶段的待办列表，并开始阶段 1。

---

## 阶段 1：上下文建立

加载 AGENTS.md 已有的项目架构概览和知识库导航；按需加载与本功能相关的 docs/ 文档（architecture、arch-decisions/index 等），跳过已在上下文中的内容。

如果用户在此之前已运行 `discuss` skill 并有 spec 文档，直接加载 spec，跳到阶段 2。

用渐进式对话澄清需求：**按主题分批提问**，无依赖的问题合并同批，每个问题附带推荐和理由，选择题优先。

---

## 阶段 2：代码库探索

**目标：** 理解与本功能相关的现有代码和模式。

并行启动 2-3 个 `explore` 子代理，分别聚焦不同维度（类似功能实现、架构和模块边界、测试/扩展点）。每个子代理返回 5-10 个关键文件列表；读取这些文件后再继续。

---

## 阶段 3：架构决策与高风险拦截 (Smart Gates)

**取消机械审批 Gate。** 采取**乐观决策**原则：
- 面对可行的架构方案，选择最符合当前项目约定或最简单的一个。
- 在回复中用一句话说明你的选择及理由，然后直接推进，**不等待用户确认**。
- **高风险拦截栅栏（Smart Escalation Gate）**：只有遇到以下情况，才使用 AskUser 提问拦截：
  1. 破坏性变更（修改数据库 Schema、删除或重构现有对外 API）。
  2. 敏感阻断（需要外部 API Key、牵涉用户隐私）。
  3. 巨大范围蔓延（预估修改超过 8 个文件，或引入全新的重量级框架）。
  4. 业务逻辑存在不可调和的死胡同。

---

## 阶段 4：任务规划与启动

**抛弃繁重的 Exec-plan 文档。**

1. 直接使用 `TodoWrite` 工具在内存中列出 3-5 步核心开发任务。
2. 统一执行 `git checkout -b feat/<feature-name>` 创建轻量级的本地工作分支（若未处于合适的分支上）。
3. 立即进入代码修改。

---

## 阶段 5：自主实现与测试验证

遵循**务实测试驱动（Pragmatic TDD）**原则进行单体实现：
- 同时编写业务代码和测试代码。
- **验证优先**：强制在终端运行 lint 和测试命令（如 `pytest` 或 `npm test`），必须看到绿色的 PASS 输出才能声称该 Todo 步骤完成。
- 根据终端报错自主进行修复，无需专门启动额外的“审查子代理”。

---

## 阶段 6：总结与收尾

如果需要长期记录关键决策，使用 `dev-docs-maintain` 同步更新相关文档。
任务完成后，向用户输出简洁总结：构建了什么、关键决策、以及所有通过的测试证据。不再强制要求多项选择的收尾流程。

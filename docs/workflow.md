# 工作方式与 Skill 协调

用户给出目标并确认必要取舍后，Agent 在已选执行路径内连续推进授权内的实现、验证、适用审查和修复。自动能力按需组合；手动 Skill 须由用户显式启动，不被内部调用链绕过。当前边界见 [ADR-0014](adr/0014-current-baseline.md)；完整能力和安装资源见[架构](architecture.md)。

## 从当前缺口进入

明确的小改动、完整 issue 或已确认的失败可以直接实现，不强制创建 spec/ticket。只请求分析、建议、讨论、计划或草稿时，交付相应结果，不推导实施或发布权限。

事实能由仓库、命令帮助或权威来源解决时自行查证；只有不同答案实质改变目标、风险或用户偏好、且工具不能回答时提问。已确认的决定不反复重问；等待某个决定时继续不依赖它的工作。

- 计划、决定或想法需要压力测试：`grilling` 按原版问题树逐轮访谈；用户显式选择 `grill-with-docs` 时，组合 `grilling` 与 `domain-modeling`。其他目标不清的任务按实际缺口澄清，不强制进入该流程。
- 明确行为变更：`implement` 与 POD；根因不明先用 `diagnosing-bugs` 获取区分性证据。
- 需要依赖调度或跨会话恢复：`implement-spec` 可直接消费已有 spec、票据和关系；用户需要专门的规划流程时显式选择 `to-spec`、`to-tickets` 或 `wayfinder`，不为进入实施额外造票。
- 实现入口驱动 review–fix 循环；独立审查、技术研究、原型、PR 草稿和项目知识可按缺口使用自动能力；`triage`、`improve-codebase-architecture`、`retro`、`handoff` 是用户选择的手动入口，不自动扩展当前任务。

进入 `grilling` 后，当前前置条件已满足的问题组成一轮 frontier；依赖尚未回答问题的分支留到后续轮次，事实调查使用新上下文子代理。问题树收敛后仍须用户确认共同理解，不能用自动推进绕过此确认；确认前不实施。`grill-with-docs` 保留原版手动调用元数据，不是模型自动选择的讨论入口。

## 可自动验证的实现

行为变更默认从能证明消费者可见差异的失败开始，做最小通过实现；重构留到 review 阶段，在行为覆盖更完整时进行。已观察到的真实失败可直接作为起点；不为了仪式重复复现。纯重构保持现有行为，UI 查看实际画面和交互，文档核对事实与可达性，机械变更用对应工具。

永久测试保护真实行为、边界和故障机制，不钉实现、措辞或转发。并发、性能、flaky 和组件交互用覆盖这些属性的证据，浅层 mock 的绿色不能替代真实路径。实现路径由 `implement` / `implement-spec` 驱动 review–fix 循环，直到没有未解决的 blocker 或高严重度 finding，且剩余项都有明确处置；纯文档、注释、格式、已有工具完整覆盖的机械改动，或用户明确只要审查时可跳过并说明理由。审查默认把需求与工程质量分别交给独立 reviewer 并行；用户明确要求合并时才由同一 reviewer 覆盖，仍分维报告。不固定循环轮数。

## 任务图与唯一状态源

只在跨会话恢复、调度或并行有收益时拆 tickets。切片通常以可交付的垂直结果为单位；横向机械迁移可按真实依赖分批，必要时明确最终组合验收。依赖表达真实 blocker，而非偏好的实施顺序。协调者从当前 tracker 取 ready frontier，为独立工作指定新上下文子代理、明确写所有权；共享文件串行或由唯一整合者处理。

实现与 tracker 回写是两种授权。选定后端是执行状态唯一来源：native 支持时用 native，不支持时用约定正文，不复制同一关系。一个本地图由一个协调者写状态，多会话无可靠原子机制时串行，不用标记重读冒充锁。

子代理完成返回产物、证据与限制。协调者运行整体组合行为，修复集成问题后才回写获授权的完成状态；子票完成不自动完成父 spec/map。默认工作树协作无需 Git 隔离操作，branch/worktree/commit/merge/push/PR/清理不因“实现 spec”而获授权。

## 计划、交接与恢复

需要人审、跨会话参照或外部消费者时才保存计划或交接；`handoff` Skill 仅在用户显式选择时启动。保存目标及理由、仍成立的决定、授权、证据、状态源指针和下一动作；不复制 tracker 的任务清单与进度。恢复先读当前仓库和 tracker，旧交接不覆盖更新的状态；没有 tracker 时指向可核实的现有事实，不为交接新建一套。

知识保持在项目既有位置：复用 CONTEXT/glossary 和 ADR；普通偏好不一律建 ADR。文档协议按目标项目执行，普通 docs 不强制转成 Bundle。知识导航、语义写入和机械扫描分别消费对应能力，不固定串行全跑。

## 证据与交付

完成声明精确匹配实际观察：调查有区分性证据，行为有真实入口或有效契约测试，UI 有实际画面/交互，性能和稳定性有同口径比较。dirty working tree 可以验收；只有 commit-bound 动作才需要提交绑定。子代理自报、模板齐全和状态变成 done 不能替代证明。

取得足够证据后交付结果及未验证面。不要为“完整”追加用户没要的文档、抽象、审查层或下一流程。真实 blocker 才需要停下来：缺必要偏好、授权、不可逆决定或工具无法取得的事实；说明具体缺口并先完成不受影响的工作。

## 副作用边界

起草 PR 不发布；生成 wizard 不执行；只读 triage 不改标签、assignee 或 issue。已有授权清楚覆盖具体目标和范围时不重复询问；范围变化或授权缺失时在执行点确认。commit、push、merge、删除、权限、秘密、生产和高影响动作遵守宿主及用户边界，测试绿色不是批准。

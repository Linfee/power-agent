# 工作方式与 Skill 协调

用户给出目标并确认必要取舍后，Agent 在授权内连续推进实现、验证、适用审查和修复。Skill 是按需能力，不是等用户逐个点击的阶段。当前分工见 [ADR-0012](adr/0012-matt-led-skill-fusion.md)。

## 从当前缺口进入

明确的小改动、完整 issue 或已确认的失败可以直接实现，不强制创建 spec/ticket。只请求分析、建议、讨论、计划或草稿时，交付相应结果，不推导实施或发布权限。

事实能由仓库、命令帮助或权威来源解决时自行查证；只有不同答案实质改变目标、风险或用户偏好、且工具不能回答时提问。已确认的决定不反复重问；等待某个决定时继续不依赖它的工作。

- 目标或取舍未清：`grilling`；讨论需要保存时 `grill-with-docs` 复用领域与文档协议。
- 明确行为变更：`implement` 与 POD；根因不明先用 `diagnosing-bugs` 获取区分性证据。
- 需要依赖调度或跨会话恢复：按需使用 `to-spec`、`to-tickets`、`implement-spec`；复杂决定地图可用 `wayfinder`。
- 审查、技术研究、原型、PR 草稿、项目知识或 Harness 评估，可以直接选择对应入口，不先走其他站点。

## 可自动验证的实现

行为变更默认从能证明消费者可见差异的失败开始，做最小通过实现，再在保护下重构。已观察到的真实失败可直接作为起点；不为了仪式重复复现。纯重构保持现有行为，UI 查看实际画面和交互，文档核对事实与可达性，机械变更用对应工具。

永久测试保护真实行为、边界和故障机制，不钉实现、措辞或转发。并发、性能、flaky 和组件交互用覆盖这些属性的证据，浅层 mock 的绿色不能替代真实路径。审查同时看需求与工程质量，独立投入按风险和未知决定，不固定 reviewer 数或循环轮数。

## 任务图与唯一状态源

只有需要调度消费者时才拆 tickets。切片以可交付的垂直结果为单位，依赖表达真实 blocker，而非偏好的实施顺序。协调者从当前 tracker 取 ready frontier，为独立工作指定新上下文子代理、明确写所有权；共享文件串行或由唯一整合者处理。

实现与 tracker 回写是两种授权。选定后端是执行状态唯一来源：native 支持时用 native，不支持时用约定正文，不复制同一关系。一个本地图由一个协调者写状态，多会话无可靠原子机制时串行，不用标记重读冒充锁。

子代理完成返回产物、证据与限制。协调者运行整体组合行为，修复集成问题后才回写获授权的完成状态；子票完成不自动完成父 spec/map。默认工作树协作无需 Git 隔离操作，branch/worktree/commit/merge/push/PR/清理不因“实现 spec”而获授权。

## 计划、交接与恢复

需要人审、跨会话参照或外部消费者时才保存计划或 handoff。保存目标及理由、仍成立的决定、授权、证据、状态源指针和下一动作；不复制 tracker 的任务清单与进度。恢复先读当前仓库和 tracker，旧 handoff 不覆盖更新的状态。

知识保持在项目既有位置：复用 CONTEXT/glossary 和 ADR；普通偏好不一律建 ADR。文档协议按目标项目执行，普通 docs 不强制转成 Bundle。知识导航、语义写入和机械扫描分别消费对应能力，不固定串行全跑。

## 证据与交付

完成声明精确匹配实际观察：调查有区分性证据，行为有真实入口或有效契约测试，UI 有实际画面/交互，性能和稳定性有同口径比较。dirty working tree 可以验收；只有 commit-bound 动作才需要提交绑定。子代理自报、模板齐全和状态变成 done 不能替代证明。

取得足够证据后交付结果及未验证面。不要为“完整”追加用户没要的文档、抽象、审查层或下一流程。真实 blocker 才需要停下来：缺必要偏好、授权、不可逆决定或工具无法取得的事实；说明具体缺口并先完成不受影响的工作。

## 副作用边界

起草 PR 不发布；生成 wizard 不执行；只读 triage 不改标签、assignee 或 issue。已有授权清楚覆盖具体目标和范围时不重复询问；范围变化或授权缺失时在执行点确认。commit、push、merge、删除、权限、秘密、生产和高影响动作遵守宿主及用户边界，测试绿色不是批准。

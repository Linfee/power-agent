# Skill 与 Harness 设计指南

以 Matt 的轻量能力组织为主干，保留能改变行动、判断、授权或验收的 Power 知识。当前默认见 [ADR-0012](adr/0012-matt-led-skill-fusion.md)。

## 先找行为缺口

新增文字前，说明没有它时模型会在哪类任务做错什么。默认行为复述、统一章节、固定步数和无消费者的模板通常不值得加载。值得保留的是不明显的领域事实、真正改变选择的条件、授权/安全/数据边界，以及能接受或推翻结果的证据。

Skill 要具体到排除坏选择，也要保留不同的正确路径。硬边界与偏好分开：机器协议、安全和授权可以精确，工具、批量、候选、子代理与输出样式随任务选择。主文、references 和示例必须使用同一判断，不在示例里重新加入正文已删的强制流程。

## 整包组合与渐进披露

25 个 Skill 整包分发、均可自动调用，不承诺独立安装。可以具名消费另一能力，把同一判断只保留在一个权威位置；不能用调用关系推导所有任务必跑的长链，也不能只告诉用户“接下来手工调用某 Skill”。已有普通材料足以完成时直接消费。

主文保留进入任务必需的判断和边界；低频专门知识按需引用；确定性动作交脚本。比较整个实际阅读路径，不以主文缩短但强制多读证明精简。引用和脚本从实际安装位置解析，不能假定业务 cwd 含源码。

Description 只负责触发，短且可区分，不塞流程或近义词堆叠。主文不要求用户逐阶段批准；真正偏好或授权才需要人介入。

## 证据与机械化

验收观察消费者关心的行为，用能推翻错误实现的最小证据。结构、目录和引用检查只证明可达性，不证明自然触发或实际执行；模型自评与字段齐全不算结果证明。

类型、lint、schema、测试、hook 和脚本可以可靠裁决的规则不长期堆在 Prompt。精确 schema 只服务真实机器消费者，不给所有 Skill 统一报告格式。永久测试保护行为、边界和失败机制，不钉文案或内部实现。

## 维护与对照

变化同步触发、正文、references、脚本、索引、具名消费者与来源。去掉 obsolete 文件和别名，保留许可证及 credits；普通局部修改不增加仪式文档。

需要行为对照时，在相同模型、工具、输入、授权和验收下比较基础、来源或候选，保留实际加载范围、执行轨迹和产物。少量案例只能支持对应场景，不能声称普遍提升；显式加载不能记成自然发现。不建立无持续消费者的永久评测平台。

模型或宿主升级后重新检查哪些机制还承重。删除默认行为复述和无消费者模板；安全、授权和实际机器协议不能以“模型应该懂”为由删掉。方法细节见 [`writing-for-agents` 的判据](../skills/writing-for-agents/references/criteria.md)。

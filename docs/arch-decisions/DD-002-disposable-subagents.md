# DD-002: 子代理一次性原则

## 背景

exec-plan-runner 等 Skill 需要通过子代理执行具体任务。需要决定子代理是可重用的还是一次性的。

## 约束

- 子代理上下文不能被前次交互污染
- 修复问题时必须有干净的起点
- 主代理负责编排，不自己写代码

## 方案对比

| 方案 | 优势 | 劣势 | 复杂度 |
|------|------|------|--------|
| A: 重用子代理 | 保留上下文、减少重传 | 上下文污染、错误累积 | S |
| B: 一次性子代理 | 干净上下文、可预测行为 | 需要完整传入问题描述 | M |

## 决定

选择方案 B：子代理是一次性的。主代理不与同一子代理进行多轮对话。每次需要修复都启动新子代理，将问题描述和上下文完整传入。

## 后果

- 每次启动子代理需要组装完整上下文包（增加 prompt 工程工作量）
- 避免了错误上下文累积导致的连锁失败
- 修复循环有明确的 3 轮上限，超过则 escalate

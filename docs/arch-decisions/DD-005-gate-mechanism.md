# DD-005: Gate 机制强制人工确认

## 背景

Agent 在自主执行过程中可能偏离方向，尤其在架构选择和破坏性操作前。需要决定是否以及在哪些环节强制人工介入。

## 约束

- 关键决策（架构选型、实现批准）不可完全自动化
- Gate 不能过多导致流程僵化
- Gate 位置必须在"做出承诺"之前，而非之后

## 方案对比

| 方案 | 优势 | 劣势 | 复杂度 |
|------|------|------|--------|
| A: 无 Gate，全自动 | 快 | 方向错误时浪费大量资源 | S |
| B: 关键决策点 Gate | 平衡效率与控制 | 需要识别正确的 Gate 位置 | M |
| C: 每步确认 | 安全 | 流程僵化、效率极低 | S |

## 决定

选择方案 B：在关键决策点设置强制 Gate。具体位置：

| Gate 位置 | 触发条件 | 动作 |
|-----------|----------|------|
| discuss Step 7 | spec 完成后 | 等待用户批准 |
| feature-dev 阶段 3 后 | 澄清完成 | 等待用户确认 |
| feature-dev 阶段 4 后 | 架构方案呈现 | 等待用户选择 |
| feature-dev 阶段 6 前 | 准备实现 | 等待用户明确批准 |
| exec-plan-runner | 歧义/破坏性变更/3 轮修复失败 | Escalate 给用户 |

## 后果

- 人类掌舵方向，Agent 执行细节
- 两个人工 Gate（选方案、批准实现）防止 Agent 在错误方向上浪费资源
- Escalation 机制为自动化流程提供安全阀

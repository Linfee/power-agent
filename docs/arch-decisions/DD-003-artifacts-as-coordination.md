# DD-003: 产出物作为协调介质

## 背景

Skill 之间需要协调和传递信息。需要决定协调机制：直接调用、共享内存、还是通过文件。

## 约束

- 协调过程必须可追溯、可版本化
- 下游 Skill 无需了解上游实现细节
- 产出物对人类和 Agent 都可读

## 方案对比

| 方案 | 优势 | 劣势 | 复杂度 |
|------|------|------|--------|
| A: Skill 直接调用 | 低延迟 | 紧耦合、不可追溯 | S |
| B: 共享内存/状态 | 灵活 | 难以版本化、调试困难 | M |
| C: 产出物（文件）协调 | 可追溯、可版本化、松耦合 | 需要约定文件格式 | M |

## 决定

选择方案 C：Skill 之间通过写入仓库文件来"传话"。spec 文档、exec-plan 文件、代码变更、docs/ 文档构成产出物链。下一个 Skill 读取这些产出物作为输入。

## 后果

- 需要明确定义产出物格式和存放位置（specs/、exec-plans/、docs/）
- 产出物天然版本化（Git）
- 中断恢复变得简单——读取已有产出物即可继续
